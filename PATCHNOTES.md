# Tokenade — what's new

## 1.1.7

- `tokenade query <symbol> --file <path>` answers about one file instead of the whole repository. A common name is the case where `query` helps least: `Format` matches **219 symbols** here, so the thirty ranked hits you get back can easily contain none from the file you were actually looking at. Measured over this machine's transcripts, six real calls spelled `--file` and were told only that the flag does not exist — a caller reaching for exactly the right idea. The flag is repeatable, and a path suffix is enough: `docs.rs`, `src/docs.rs` and the full relative path all name the same file, while a directory scopes everything under it. The scope applies before the ranking cap, not after, so a file with thirteen hits reports thirteen rather than whatever survived a repository-wide cut, and it applies to all three of `query`'s renderings — the default listing, `-o count/paths/outline` and `--json`. A path that names nothing answers nothing, and says which symbols were close.

- The release now builds and tests the Windows ARM target on a drive that has room. Both Windows targets are cross-built on one VM, and only one of the two configurations had been moved off the system drive when it filled up — so the x64 leg built and the ARM leg died twenty minutes in with `unable to open output file '…regext.o': No space left on device`, blamed on a C file in a regex library. The drive had 0.0 GB free of 49.4 while the other had 43. Both legs now share the roomy one, and the VM build refuses up front with `only N GB free at <path>` instead of walking into the wall — the same guard the local build has always had, which the remote side only had half of.

- `tokenade gain` says what period its numbers cover. The `last 7 days` view has always named its window — the default view, which is every operation ever recorded, named nothing, so a lifetime average across months of use, several tokenade versions and a ledger rotation read as the rate you are getting today. On this machine that headline covers **96 days and 33,250 rows** behind a bare `saved: 93.2%`. The header now reads `tokenade gain (everything recorded: 96 days, since 2026-05-28)`, taken from the ledger's own earliest row rather than from an install date, and `gain --json` carries a `span` object (`first_ts`, `last_ts`, `first_iso`, `last_iso`, `days`) because a machine reader cannot see a header. A ledger whose rows predate the timestamp field reports `null` rather than a guessed span.

- Tokenade works when your Claude Code config is not in `~/.claude`. Claude Code reads `CLAUDE_CONFIG_DIR` before it reads `~/.claude` — one line in its own source: `process.env.CLAUDE_CONFIG_DIR ?? join(homedir(), ".claude")` — and tokenade honoured it in none of its hundred-odd paths. The result was not a degraded install but no install at all: measured on a clean machine with the config relocated, `tokenade install --only claude-code` answered **"no AI coding agent detected on this machine"** and wrote nothing, because the directory it looks for is one you do not have. Same machine, config in the default place: install succeeds and your settings file gains 22 hook references. Detection, hook installation, `settings.json`, the global `CLAUDE.md` and the transcript scan that feeds `gain`, `discover` and the dashboard all follow the variable now. `.claude.json` follows the rule Claude Code actually uses, which is not the one the default layout suggests: it sits beside the config directory when the variable is unset and **inside** it when it is set. Project-local `.claude/settings.json` is deliberately untouched — that one lives in the repository and the variable does not move it.

- `tokenade web` names the retired `kind=` parameter instead of trying to fetch it. `kind=page` and `kind=serp` were MCP tool parameters, dropped with the zero-MCP pivot, and the retirement reached the documentation and nothing else: `--kind page` got the generic "unknown flag" answer, and the bare `kind=serp` was read as a second URL to fetch. `tokenade web page.html kind=serp` served the page, printed `kind=serp: fetch/read failed` about a target nobody named, and **exited 1** — a run that worked, reported as a failure to any script or `&&` chain reading the exit code. Measured here, 19 real `web` calls across 10 sessions still carry one of the two spellings, which is a doc that taught it for years rather than a caller guessing. Both now answer that the parameter no longer exists and that `web` tells a search-results page from an article by itself, so there is nothing to replace it with.

- `tokenade llm-proxy autostart --enable` tells you when the service it just installed is not going to answer. It confirmed that the supervisor KNEW the unit and stopped there, which is a different question from whether the proxy is running: with something else already holding 127.0.0.1:8787, `systemctl --user enable --now` exits 0, `is-enabled` answers `enabled`, and the service is dead five seconds later on `Address already in use`. The command printed `confirmed by ...: the supervisor knows this unit` over a proxy that would refuse every connection, and every agent pointed at that base URL would have failed each turn with nothing to read. It now asks the second question too, twice a second apart because the supervisor returns before the proxy has tried to bind, and a unit that is registered and not serving is reported with the supervisor's own words (`auto-restart exit-code`) at exit 1, naming the likely cause and the line that takes the unit back off. On macOS and Windows the second question is not asked rather than guessed: the state word those two print is not verified here, and a wrong guess would report a healthy install as broken.
- The systemd unit no longer gives up for good after five failed starts. `Restart=always` was capped by systemd's default start limit, so a proxy that could not bind burned its five tries in five seconds and stayed `failed` even once the port freed — measured 2026-08-31, still dead twenty-five seconds after the process holding the address had exited, on a unit that reported itself enabled. The unit now sets `StartLimitIntervalSec=0`: the same run kept retrying and came back on its own four seconds after the address freed, with nothing asked of you. This matters most at boot, where a transient conflict is exactly the kind of thing that resolves itself a moment later.

- `tokenade query <name>` names the symbols you probably meant when it finds nothing, instead of answering `no symbol matching 'name'` and stopping there. Measured over this machine's transcripts, 28 of 196 real `query` calls came back empty — against 2% for `skeleton` and `impact` — and 247 of the 425 code-intelligence calls ran a `grep` in the same command, hedging against exactly that answer and paying for both. The misses are wrong-word, not mistyped: `cmd_mcp_wrap` is five edits from `cmd_mcp_proxy` and no spell-check pairs them, but they share the words `cmd` and `mcp`. It now answers `no symbol matching 'cmd_mcp_wrap' — closest indexed: cmd_wrap, mcp_wrap, cmd_mcp_proxy`, and the same rule turns `uninstall_shim` into `uninstall_path_shim` and `split_segments` into `split_chain_segments`. A name that shares nothing but a filler word still gets the bare refusal: a wrong suggestion on a refusal costs more than none. Both of `query`'s renderings say it — the default one and `-o outline`, which is the list itself.
- `tokenade mistake list` refuses a flag it does not implement instead of listing anyway. `--json` is real there and every other spelling was discarded in silence, so `--jsonl` or a mistyped `--json` printed the human table at exit 0 to a caller that had asked for JSON. Nothing here rewrites anything, so the cost was a wrong answer rather than a wrong action — it was still the answer the rest of the CLI refuses to give. A bare `tokenade mistake`, `mistake list` and `mistake list --json` are unchanged.
- `tokenade mcp-wrap install` and `mcp-wrap uninstall` refuse a flag they do not implement instead of rewriting every server's launch command. The name of the server to act on was read as "the first argument that does not start with a dash", so an unimplemented flag was thrown away and the subcommand ran with no name — which means all of them. Measured on a config holding two servers, `mcp-wrap uninstall --zzbogus` restored both and reported success at exit 0; a typo aimed at one server rewrote the config for every server the agent had. `--all` is documented and had never been implemented either: it worked for the same reason it was discarded. It is a real flag now, `--al` is told which flag it is one character from, and a second server name is refused rather than silently dropped. `mcp-wrap report --json` no longer answers a machine reader with the human table at exit 0.
- `tokenade read <source-file> --prompt "…"` answers the question instead of handing back the whole file without a word. Retrieval runs on the document path and on the plain-text path; a source file takes a third path — comments stripped, code kept — that returned before the question was ever consulted, and did not receive it. Measured on a 24,006-token `.rs`, the output was byte-identical with and without the flag and nothing was printed to say so. It now answers there too: the same file and question come back at 3,154 bytes against 57,598, and the banner reads `mode=comments+scoped` with the token count of the answer rather than of the file. The silence fell on exactly the files too large to read whole, which is the only case where asking is worth anything.
- `tokenade gain` counts the source files it folds. Reading one through the CLI stripped its comments — 8,968 tokens down to 3,839 here — and wrote no ledger row at all, while the same file opened through your agent's Read hook was credited. One rule behind two doors, and the saving existed only when it came through the other one.
- An unknown flag now names the real flag you probably meant on every command, not just on the destructive ones. `tokenade skeleton x.rs --budgt 50` answered "unknown flag '--budgt'" and sent you to `--help`; it now adds " — did you mean `--budget`?". A token close to nothing still gets no suggestion, because a wrong guess on a refusal costs more than none.
- `tokenade trust-filters --help` shows the command's own help instead of "this command has no dedicated help yet". The text was written and unreachable: it explains that project-local filters in a cloned repository cannot rewrite your agent's output until you trust them, and that trust is per file content.
- `tokenade watch`, `tokenade trust-filters` and `tokenade report` now refuse a flag they do not implement instead of ignoring it. Each silence cost something different: `watch` dropped every argument it was given, `trust-filters --lst` trusted every project filter when you had asked it to only list them, and `report --dry_run` skipped the dry run and went for the real collection. They now name the command, name the token and exit 2, pointing at `--help` for the flag list — the wording the rest of the CLI already uses. `tokenade statusline` is deliberately left permissive: its caller is your agent's status-line hook, and refusing a flag from a newer agent version would blank the line.
- `tokenade healthcheck` gives one answer about your hook binaries instead of two contradicting ones. Two checks asked the same question: one read the `sh -c '…'` command shape correctly, the other took the first whitespace token as the binary path — always `sh` — so it reported `all agent-config hook paths resolve` three lines above `1 hook command(s) reference a non-existent binary`, about the same binary. The check whose message reads "hooks silently dead" was silently dead itself, and its test used a command shape the installer never writes. It now uses the shared reader, covers every agent's config rather than Claude Code's alone, and the duplicate is gone.
- `tokenade discover --days N` counts the last N days, not the files touched in the last N days. The cutoff was applied to each transcript's modification time, so a session opened in June and appended to this morning contributed all of its June entries under a "last 30 days" header. Measured here, 6 of 547 files straddled the boundary and carried 44,574 tool results worth 25.5 MB — 21 % of the reported bytes. The rows move by a quarter to more than half: Bash 96,324 calls / 79.9 MB becomes 69,132 / 59.5 MB, Read 9,206 / 30.3 MB becomes 4,345 / 28.7 MB. An entry with no readable timestamp is still counted, and the session count now names only the sessions that actually contributed.
- `tokenade exec` tells you when the shell left a backslash in your script instead of leaving you with `SyntaxError: unexpected character after line continuation character` — a line continuation nobody wrote. `--script "print(\\"hi\\")"` works because double quotes drop the backslashes; `--script 'print(\\"hi\\")'` passes them through, and nothing runs at all. Measured over 90 days of real use, 62 exec calls died that way and the count rose every month. The note counts the escaped quotes, says the script never parsed, and points at `--script-file <path>` or `--script -`, which have no shell quoting to get wrong. A script that runs is never lectured: the check keys on the interpreter's own error plus the backslash still being there.
- The subagent split `tokenade discover` now reports says what it is not. A deliberate Read under ~25,000 tokens is served whole on purpose — the agent asked for that file, and every later reference to it is served from the prompt cache while a re-fetch re-pays a whole turn. The doubt was whether that holds in a subagent, whose context is discarded at the end of the task; measured over 478 subagent reads of 20 KB or more, a median of 27 assistant turns follow the read inside the same subagent and none has two or fewer. The line carries that number, so a lopsided channel reads as a place to look rather than a leak to plug.
- `tokenade discover` shows where a channel's bytes came back: the main session, or a subagent. Its biggest finding was hidden inside its biggest row — summed, `Read` reads "9,206 calls, 30 MB" and looks like one healthy channel; split, it is 6,609 calls returning 2.6 MB in the main session and 2,598 returning 27.3 MB inside subagents, 401 bytes per read against 10,633. The table gains an `in subagents` share, `--json` gains `sidechain_calls`/`sidechain_bytes` (a subset of the totals, not a second bucket), and a channel that lopsided is now named with the lever that applies there rather than left for you to spot.
- `tokenade semantic` answers under the name it is documented by. Every message it emitted — the usage line, the unknown-flag refusal, the bad `-o` value, the empty-query refusal — opened with `tokenade ask:` and pointed at `tokenade ask --help`, while `list-commands`, the top-level help, and `tokenade ask --help` itself all call `semantic` the command and `ask` an alias. The project rules tokenade scaffolds into `CLAUDE.md` teach `semantic`, so the one name being taught was the one name the refusals never used. `ask` and `sem` keep working and now answer as `semantic` too.
- `tokenade search "q1" "q2" …` answers every query in the batch. Past the third, the tail came back empty with `all-engines: rate-limited` — a message about a wall nobody hit: each query reserves up to three search engines for the whole of its fetch, and the earlier queries of the same batch were holding all of them. Measured over 30 days of real use, a query in position 1 of a batch was refused 14 % of the time and one in position 4, 87 %. Queries now go in waves sized on the engines actually usable at that moment: the same five-query call that returned four answers and one empty now returns five.
- A line a command actually printed stays findable after tokenade folds the output. When a fold was deep enough that the remainder was still worth stashing, the pointer over what you were SHOWN silenced the pointer over the raw bytes — so the only `expand-ref` hash you got named a stash the fold had already emptied. Grepping it for a line that was in the output answered "0 matching line(s) of 4 total", which reads as "that string was never printed". Measured on a 252-line output that came back as a 3-line stash; it now answers with the line, out of 252. When a pointer already covers the complete bytes nothing is added — one hash, whole output.
- The refusal you get from `tokenade raw grep|cat|sed|…` says what is actually true. It claimed those compactors are "lossless at line granularity" and offered `expand-ref` for "the verbatim bytes": measured on 1,200 lines, grep folds to 2 lines and cat/sed/awk to 154, and the stash holds what the fold produced — on a 25,933-byte input `expand-ref --raw` returns 16,179 with the dedup collapse already in them. The refusal stands (re-running spends the first call's tokens again) but it now names what the stash holds and the two routes that do return the exact bytes: read the source the command read, or `TOKENADE_FORCE_BYPASS=1`.
- `tokenade discover` ranks tools by what they RETURN, which is what a compactor stands between. It was ranking them by the size of the request, so `Edit` and `Write` — bytes you wrote, that nothing can compact — came second and third, while `Read` sat fourth despite returning more than twice what its requests weigh. On a 30-day sample: Edit 38.3 MB requested against 3.0 MB returned, Write 16.2 MB against 0.5 MB, Read 13.5 MB against 30.0 MB. The column is now labelled "bytes returned to the agent".
- After an auto-compaction, the recovery note offers only the folds THIS session made. The stash is one directory shared by every agent on the machine and the note picked its hashes by timestamp alone, so it could hand you `expand-ref` targets another session had produced — real bytes you never saw, offered under "raw bytes that tokenade folded earlier". Measured locally, more than one session was active in the preceding six hours at half of all moments. A session with nothing recorded is now offered nothing rather than inheriting the directory.
- When a fetched page comes back hollow, the note answers the status question instead of asking you to. Both hollow-page banners ended with "Check the HTTP status to tell them apart" — a value you do not have and tokenade does: across 37 real deliveries, 26 carried no status anywhere in the message and the other 11 stated it three lines above. The note now reads either "The server answered HTTP 404, stated above — a status-level refusal" or "no status note precedes this … so nothing here is a status-level refusal: an empty shell points to text rendered client-side".
- A comma inside brackets or quotes is no longer read as a question separator in `--prompt "q1, q2"`. `list every file (full paths, no truncation), and every .scm file` was split into three retrievals, the middle one `no truncation)` — a fragment closing a bracket it never opened, given a full retrieval budget and returned under its own `### Q2` heading as if it were a question you asked. Measured across 116 real prompts, 15 carry such a comma. Six genuine batches that were being declined now split as intended.
- When a comma-separated prompt is treated as one question, the notice now quotes the part that caused it (`"product description" is too short to stand on its own — 2 of the 3 parts fall under 3 words`) instead of restating the rule. One short part declines the whole batch, so a six-topic prompt could be refused by the single word at the end with no way to tell which.
- `tokenade map <path>` narrows the structure map to one directory or file instead of refusing. The refusal it replaced offered only "run it with no path to see the whole workspace", which is what you were narrowing away from. The header, the directory list, the top-files list and `--json` all report the narrowed set — on this repository, 5,625 bytes for the whole map against 1,026 for one subtree — and a path the index does not hold says so rather than printing an empty map. `src/net` no longer matches `src/network/`, and a second path in the same call is refused rather than silently ignored.
- `tokenade query -o outline` says when its list was cut. The command shows at most 30 declarations, and `--json`, `-o count`, `-o paths` and the default render all reported the cut; `outline` — the mode whose whole output is that list — returned exactly 30 lines with nothing said, so a name with 77 declarations looked like a name with 30. Measured on a mid-sized Rust tree, the cap binds on 33 of 80 real function names. The cap itself is unchanged, and a complete answer gains no extra line.
- `tokenade discover` names what is actually left to wire. With the hook installed it said "everything else is already wired" while holding a list of untouched traffic, and `--json` reported tools the hook already compacts as opportunities — Bash among them, sizing a saving that had already been taken. It now lists the MCP tools a hook matcher cannot reach, with the `mcp-wrap install` that covers them.
- The one-time local model download survives a bad connection. A server that answers and then goes silent used to hold the download for the full hour before the retry, four times over; it is now abandoned after two minutes of silence (`TOKENADE_STREAM_STALL_SECS` if your link's silences are normally longer). Because a dead link now fails fast, the budget for a slow one is doubled: ~700 MB at 97 kB/s instead of 194 kB/s, so slower connections can finish at all.
- Asking a folded blob a question labels its passages honestly. In a document with no headings — code, a log, most command output — every passage was labelled the document's intro, including ones drawn from the middle of a 1,500-line blob. Only the opening passage says so now; the rest say they continue, which claims no position.
- Refusing a flag reads the same whatever command you typed: the command is named, the flag is quoted, and the help it points you at is that command's. `pack` printed the flag unquoted and pointed at a bare `--help` that named no command.
- `expand-ref --grep` tells you which kind of miss you got. "0 matching lines" read the same whether the term was absent or merely spelled with different case, and on the recovery command that reads as an answer. A case-only miss now says how many lines would match and names the new `--ignore-case` (`-i`), which folds case on both sides; a term that is genuinely absent says so instead.
- `expand-ref` refuses a flag it does not know instead of ignoring it. A one-letter typo silently changed the answer: `--raww <hash>` returned the "too large to dump whole" banner where `--raw` returns the blob, exit 0 either way and nothing said. A mistyped `--grep` now names the flag rather than blaming your pattern for not being a hash, and `--` ends the flags as it does elsewhere.
- A command that exits 0 while its output reports a failure is called out in more of the cases that actually happen: a build tool refusing the command it was given (`error: no bin target named ...`, `error: test failed ...`) and a failing `go test` or jest run. The notice now quotes the line that reports the failure instead of the pattern that matched it. A pipeline reports only its last stage's status, so `cargo test | head` looks green however the tests went.
- A page fetched by `scout` or by the agent's fetch tool is now bounded in memory. The body was read whole after decompression, so a 65 KB download from a hostile or broken origin could become 67 MB of resident memory with nothing in between; a body cut short now says so instead of passing for the whole page.
- `web`: a table cell holding inline code with a `|` in it no longer breaks the row. `<td><code>0|1</code></td>` produced a row of four columns under a header of two, so the values stopped lining up with their headings.
- `web`: a paragraph whose text begins with `#` is no longer read as a heading. On a twelve-section page carrying one such line, the outline announced three sections and attributed the other nine to a second document that does not exist.
- Eleven commands whose name ends in `mod` — `chmod`, `lsmod`, `usermod`, `insmod`, `rmmod` among them — are compacted by the code written for them. That code shipped but was never reached, so their output came back whole; a listing of loaded kernel modules goes from a hundred and twenty lines to forty.
- Where a command has both a hand-written compactor and a table-driven one, the one that actually runs is now the one its output was measured against, on every platform. The two agreed everywhere they were checked, and the check had been reading the wrong one on five commands.
- Code and documentation are delivered as themselves, even when their text quotes the markers of a third-party service.
- Content is treated as tabular only when its rows agree on their shape, so a snippet that merely happens to contain commas comes back whole.
- A table column that is empty in every row and left out of the result is named, so you can still ask for it.
- Terraform and other infrastructure files say when commentary has been left out, and how much; a file small enough that saying so would cost more than it saves comes back untouched.
- A search whose matches all come from a single file names that file, so every result line joins back to a path you can open.
- The health report reads as a sentence in every state, including once a bypass window has elapsed.
- `map --json` over a very large tree returns an object sized for a reply, carrying the counts and a reference that reaches the full document, so it stays something a script can parse and a session can hold.
- `skeleton` over a large batch of files now answers within a reply-sized ceiling by default, naming every file it did not fully outline so you can ask for the ones you wanted. `--budget` sets your own ceiling, and `--budget 0` returns everything.
- A line that reads as a failure now survives the fold that shortens a long, repetitive run, and the summary says how many were kept for that reason.
- The same holds wherever a long listing is shortened, including the many command compactors that keep only an opening slice: a failing line, or a failing record in key/value output, is carried through whole.
- The savings figure counts each operation once, so a script repeating one command in a tight loop no longer inflates it, and the number on your dashboard means what the metered one means.
- The savings total reported by `dashboard --json` now matches the one on screen. The two were computed separately and the machine-readable one left out a cost the printed one subtracted, so a script and a person reading the same install disagreed by about five percent.
- The dashboard now reports how much context was re-sent before its cache entry could be reused, and what set it off. tokenade has been measuring this since July and showing it nowhere; on a busy install it is the largest number on the page, and unlike the others it is one you can act on.
- Five more macOS and Windows compactors now share the implementation their Linux counterpart uses, so a correction reaches every platform at once instead of one at a time.
- On macOS, `find`, `loginctl`, `logname` and `whereis` now keep the same amount of their output as they do elsewhere, and their summaries name what was counted — paths, sessions — instead of just lines. `find` in particular was handing back a third of the listing Linux returns.
- macOS and Windows now fold container and cluster listings the same way Linux does. Two corrections shipped earlier — recognising more kinds of problem row, and never cutting a row away from its own detail lines — had only ever reached one of the three platforms.
- A shortened file listing now says where the files it left out actually live. It used to group them under the directory you searched, which restated your own question and the count you already had.
- When a folded run of log lines varies in two places of the same kind, the summary now says which is which. A line reporting two different counts used to label both of them the same way, leaving the one question the summary exists to answer unanswered.
- `pack` now returns a bundle sized for a reply by default, naming every file it left out, instead of the whole tree. On one source directory that is eight and a half megabytes reduced to a hundred and twenty kilobytes. `--budget N` sets your own ceiling and `--budget 0` returns everything, the same way `skeleton` reads those values.
- Drafting a compactor from a large sample now produces a file you can actually read. The sample is trimmed to a reviewable head, the draft says how much it kept and of how much, and the generated test still matches the bytes it embeds.
- `gain` now records how many tokens a fold set aside behind a recovery pointer, and how many were later fetched back through one. The two together say whether the shortened version was enough — a question the savings figure alone has never answered.
- A document tokenade reads but cannot get any text out of now says that plainly, instead of coming back looking like a format tokenade does not support. The file is the problem — truncated, empty or encrypted — and the message says which file and what to try next.
- tokenade now recovers from an internal failure where it is able to, instead of ending the run. The recovery paths its own code already asked for — around document extraction in particular — were switched off by a build setting; they work now, and the protections that cover what recovery cannot reach are unchanged.
- Every file tokenade rewrites on your behalf — your project instructions, an agent's settings, its MCP configuration, the trust store — is now replaced in one step. If tokenade is interrupted mid-save the previous version is still there, and a file you had kept private keeps its permissions instead of being saved back more widely readable.
- With several tool calls running at once, tokenade's own counters no longer read back as empty mid-update. A counter caught that way looked like one that had never been used, so it started over — which is why a suggestion you had already declined could come back at full frequency.
- A tool call routed through tokenade's MCP proxy always gets an answer. If the proxy is killed outright while compacting a result, the call now comes back as an error you can retry instead of leaving your client waiting for a reply that will never arrive.
- Wrapping a command can no longer cost you the command. If anything goes fatally wrong while tokenade is compacting — including inside a bundled native component — the output comes back whole and uncompacted, carrying the command's own exit code, instead of the run ending with nothing to show and a success code.
- One malformed line in one agent's transcript no longer stops the usage report. tokenade reads transcript files other programs write, and a timestamp that was not plain text used to end the whole run rather than that single record.
- `tokenade exec --script-file -` reads the script from standard input, the same way `--script -` already did. It used to answer that it could not find a file called `-`.
- When tokenade repeats a suggestion you have not taken up, each repetition is now spaced out as much as the design intends. The spacing used to widen one step behind schedule, so one extra reminder arrived at the old rate every time it backed off.
- After an edit, tokenade now points at a way to review the change that works on every file — including one your version control does not track yet, and one in a directory that is not a repository at all. It reads back as a diff against the copy tokenade already held, so there is nothing to install and nothing to stage first.
- A production build run the way you actually run it — `pnpm build`, `npm run build`, `yarn build`, `bun run build` — now comes back as a summary of what was built instead of one line per page. On a content site with a thousand pages that is tens of thousands of tokens reduced to a few hundred, and every page size that differs from its neighbours is still listed by name.
- `uninstall` now always says what it did with your data. When it cannot work out where that data lives it says so, in place of ending on a line that read as success, and it only ever names a directory under a real home.
- `tokenade health` now actually inspects your savings ledger for impossible rows. It was reading field names the ledger has never used, so it reported a clean file whatever the file held.
- A support report now dates your install from your whole history rather than from whatever the ledger had not yet rotated out. On this install that is the difference between six weeks and ten.
- `tokenade gain` now reports your whole history too. On a long-running install it was showing under a third of the operations it had actually compacted, for the same reason the statusline was: the part of the ledger that had rotated out was left out of the count.
- Whichever route an operation takes into the ledger, the same rule decides whether it is worth recording. Code-intelligence operations routed through `wrap` used to be dropped at that gate while the identical operation on any other route was kept.
- The savings figure on the statusline now counts your whole history, including the part that has been rotated out of the live ledger as it grows. On a long-running install it was reporting a third of what the dashboard reported for the same data, and the gap widened with every rotation.

- `.html`, `.htm`, `.vue`, `.svelte` and `.astro` files are indexed at last: their declarations live inside a `<script>` block, which nothing descended into, so `tokenade query`, `skeleton` and `semantic` found nothing at all in a Vue, Svelte or Astro project, and nothing from the scripts of an HTML page. The tag is recognised whatever its case, and every symbol carries its real line in the file. What does not enter the index: data blocks (`application/json`, `text/template`, and the like), minified third-party libraries inlined into a page, and the single-character names they leave behind — on one library whose test suite contains 737 saved web pages, that avoids 11,000 symbols such as `r` or `i` which would have ranked the real API behind them.
- The debug log (`TOKENADE_DEBUG_LOG`) finally records every case where the 50,000-token output ceiling fires. The event existed but only one of the four paths emitted it: a ceiling applied to a web page or to a file read left no trace at all, which made a "truncated output" diagnosis impossible to confirm.
- A command preceded by a label (`echo "=== step 2 ==="; make build`) is compacted again by the real command's compactor. It was routed as an `echo`, which cost about 15% of the fold and lost the grouped summary of repeated lines. A leading `cd` was already handled; `echo`, `printf`, `sleep`, `true` and `:` are handled now too, and a chain containing only those is still routed as itself.
- Output more than half of which has been folded now carries its `tokenade expand-ref` pointer, even when it is short. The threshold looked only at the absolute number of tokens removed, on the assumption that "you can simply run the command again" — which is untrue for a snapshot of machine state: `systemctl list-units` lost 90% of its output, `df -h` 60%, `lsblk` 57%, with no way back to the original bytes, and running them again gives different bytes. Tiny outputs still write nothing to disk.
- `tokenade ask --budget N` shortens results before dropping them. When the ceiling was reached, the following results disappeared entirely while room remained: on a real search at `--budget 60`, two files were named and eight set aside, leaving sixteen tokens of the ceiling unused. A result that no longer fits whole now keeps its score and its path, and loses only the list of matching terms.
- When `tokenade exec` kills a script at the deadline, the message now says how to lift the limit: `--timeout <secs>` (default 30, maximum 600), and it makes clear that the output already shown is what the script had produced before it was stopped. The flag existed but was named only in `--help`, which made the timeout the leading cause of `exec` failures.
- An oversized custom compactor file (`.tokenade/filters/*.toml`) is refused on its size, before being read. That directory arrives with a cloned repository and is re-read on every command, so a 40 MB file — or a 2 GB one — charged its reading to every command you ran in that repository. The ceiling is 256 KiB, twenty times the largest compactor definition ever measured, and the refusal appears in `tokenade healthcheck` with its reason.
- A build or test whose failure the exit code swallowed is now named. A pipeline reports only its last stage's status, so `cargo test 2>&1 | tail -40` exits 0 however the tests went — and `| tail`, `| head`, `| grep` are exactly the operations reached for to keep output small, so the error always falls on the side of looking green. Measured across 89,151 recorded commands: 5,781 pipe a build or test runner into such a sink, and 830 of those handed back unambiguous failure evidence under a success status, against 13 reported as errors. Both `tokenade wrap` and `tokenade exec` now say so in one line when the status claims success and the output reports a failure, reading the raw output so a marker the fold removed is still caught. The exit code itself is untouched: turning `cmd | head` into a failure, where the producer dies on a closed pipe every time, would be worse than the silence. A command already reporting its own failure stays silent, and so does one that merely searches for the marker.
- `tokenade read` with nothing to read no longer hands back a pointer to nothing. With no file named and an empty stdin it answered with a recovery reference for the empty string — `~0 tokens / 0 bytes, identical to a prior call` — and invited you to ask it questions, while reporting success. It now tells the two cases apart: a bare `tokenade read` is a forgotten path and says so with a usage line and a failing exit code, the same as the other commands; an explicit `tokenade read -` whose producer legitimately emitted nothing (a `grep` that matched nothing, say) is a result and not a mistake, so it stays silent and succeeds. Reading a real file or a real pipe is unchanged.
- A mistyped flag is no longer accepted in silence. On `tokenade web` anything unrecognised fell through to the list of pages to fetch, so `tokenade web --json page.html` tried to download `--json`, printed `--json: fetch/read failed`, served the real page anyway and still reported success; a dropped letter in `--max-tokens` silently abandoned the budget and turned one page into a three-target batch. On `tokenade map` an unrecognised flag was ignored outright, so `--jsn` — one letter short of `--json` — printed the human map and reported success, handing prose to a caller that had asked for JSON. Both now name the flag and fail, as `search` and `exec` already did. In the same pass, `tokenade web` with no page at all used to print nothing and report success, so a typo read as a job done — it now shows its usage and fails, like every other command.
- The outline of a long page now describes its sections instead of its pictures. Each section is previewed by its first line, and on a page whose sections open with a figure that line is the caption: one encyclopaedia article came back with all three of its sections summarised as `"[1 of 2](/media/1/342664/159005)"` and `"[lions chasing a warthog](/media/1/342664/159006)(more)"`. The outline is what you read to decide which section to open, so a caption there costs tokens and tells you nothing. A caption now yields to the prose beneath it. It is a preference and never a rejection: a section that has nothing but a figure keeps it, rather than losing its preview altogether. A sentence that merely links to an image partway through is prose and is unaffected.
- `web`: section previews no longer describe a picture. A page whose sections open with a figure was previewed by that figure's caption instead of its prose — on a Wikipedia biography, three of four sections read as image captions.
- `wrap` and `exec`: the notice that a command exited 0 while its output reports a failure now recognises a Rust panic, a compile error carrying no diagnostic code, and an uncaught Python traceback. It is also no longer disarmed by a wrapper such as `timeout 60 cargo test`, which used to read as a run of `timeout` rather than of `cargo`.
- The 24h bypass reminder now reports the number of bypasses that actually happened. A `TOKENADE_HOOK_DISABLED=1` prefix written after a `cd` line — the common shape — was honoured but counted as none, while one written at the start of the command was counted twice, and `TOKENADE_HOOK_DISABLED=1 tokenade …` counted as a bypass although it bypasses nothing.
- `pack`: the bundle header now accounts for every file in scope. Files skipped for being binary or over the per-file cap appeared in neither the included nor the omitted list and were named nowhere, so the two counts did not add up to the scope; and the header called that scope "all git-tracked files" although the bundle also carries untracked files git does not ignore.
- `web`: when a page is behind a bot wall, the notice now tells you what you can actually do — an immediate retry returns the same page, and the way through without a browser is to save the page from one you are signed in to and hand tokenade the file. It previously listed the libraries a stealth fetcher is built from, which is of no use to the caller holding the challenge page.
- `exec`: when stdout hits the cap, the notice now names `--cap`, the flag that actually raises it. It named `--stdout-cap`, which the same binary rejects with `unknown flag` — so following the advice cost you the turn and the output. `--script-file` is also documented in `exec --help` now; it worked but appeared nowhere.
- A `find` / `ls -laR` rollup now says outright that no individual path is listed in it, and how to narrow the command to see them. It summarises by directory and extension, and depending on how the output reached you there was not always a way back to the paths.
- `evict-stale --help` now documents `--models`, the flag that deletes the local model weights. Those sit on no expiry and are by far the largest thing tokenade keeps, and the help said "No flags" — so the only way to reclaim that space was not discoverable from the command itself.
- `exec --help` now lists `--sandbox`, `--sandbox-net` and `--json`. All three worked and none was mentioned, while the same help spent a paragraph explaining what the sandbox does and does not cover.
- `exec` now offers `tokenade expand-ref <hash>` when a fold drops content, as `wrap` already did. The check it used looked at how large the remaining text was, so the more effectively something folded the less likely you could get the original back — a 400-file `ls -laR` collapsed to a two-line summary with every path gone and nothing to recover them by.
- Aligned command tables are compacted even when the handler for that specific tool declines to fold them. tokenade tries the tool-specific handler first because it knows what the columns mean, but if that hands the table straight back the generic column fold is now used instead of serving the table unchanged — on `lsof`-shaped output that is 9,427 bytes down to 3,973 rather than 9,426.
- `read --prompt`: when nothing in the document answers your question, the reply says so even when what comes back is an outline. It already said so for documents handed over whole, but the outline is rebuilt after that notice is added and dropped it — and a list of section headings reads even more like a chosen answer than the document does.
- `web --prompt` now answers the question on a web page. The flag was accepted and listed in the usage line, but only the PDF/Office route ever used it — an HTML page came back byte-for-byte identical whether or not you asked something. You now get a scoped extract when the page answers, and the page plus a note saying it does not when it doesn't.
- `web --max-tokens` now says what it bounds. It caps the input that gets parsed, not the reply — the page is still converted whole so its tail is not lost — so the answer came back the same size with the flag as without, with nothing said about it. The usage line explains this, and a note tells you when the cap actually engaged.
- `skeleton --budget` now tells you when it cannot apply. Across several files the ceiling works and the footer reports what it withheld, but the first file is always shown in full — so on a single file the flag could never do anything, and did nothing without saying so.

- `skeleton`, `map` and `query` are close to twice as fast on large source files.

- The download is smaller than the last release, so a first install and every update since take less.

- `gain` no longer reports two different kinds of estimate as one number. Most of what it credits to code-intelligence commands comes from a file it actually read and counted; the rest rests on a published figure that is not ours. Each is named and totalled separately now, and both stay out of the measured headline.

It now only makes that claim while the copy is still there, and pointers to dropped copies are cleaned up instead of accumulating.
- Fixed: with several tool calls running at once, records written to tokenade's own counters could be cut into each other, so the dashboard under-reported how many secrets it had caught, and two internal counters could read back a number that was neither of the two written. Measured on a real install: 17 damaged rows in a thousand.
- Fixed: `tokenade raw 'some command'` — the quoted form every other tokenade command takes — always failed, reporting the whole command line as a file that does not exist. Both the quoted and the plain form work now.
- Reading a file through tokenade is about twice as fast, and the bigger the file the larger the gap: a 200 KB read that cost roughly four tenths of a second is now under a seventh of one.
- Wrapping a command costs about three times less than it did. On a command that finishes instantly the overhead is now around a hundredth of a second; on anything slower than that, close to nothing.
- `gain --recent` reports the last seven days instead of everything since the ledger began. A compactor rebuilt last week no longer shows the number it scored before the rebuild.
- Every wrapped command used to pay a startup cost that grew the longer you had been using tokenade — on a well-used install, around a fiftieth of a second on each of the two checks a tool call makes. That cost is now flat, and does not grow.
- Fixed, on Windows: text lifted from a page whose headings are set letter by letter came back with the last letter of each word split off, so `Hello` read as `Hell o`. Every line, and only on Windows. Those words are rejoined whole now.
- Fixed: when tokenade answered a repeated read by pointing at the copy already in your context, and that answer did not land, the fallback that serves the file in full could fail to fire while several reads were in flight — leaving the read to repeat. It fires reliably now.
- Fixed: when the recovery copy could not be written — a full disk, a read-only cache — the folded output still told you to run a command with a reference nobody had produced. It now names only the way back that still works.
- Fixed: with several tool calls running at once, the counter that tracks how much output a session has been handed lost some of them, so a context-heavy session could look light and never get the tighter handling it was due.
- `evict-stale` now reports the local-agent model weights it holds — the largest thing tokenade stores and the one nothing ever swept — and `--models` removes them.
- `healthcheck` now says how much disk tokenade is holding and what the biggest part of it is. Past a few gigabytes it also says how to get it back.
- tokenade now keeps its own disk use inside the limits it always documented. Two of those limits were only ever applied by a command you had to run yourself, and the rest had none at all, so what tokenade held on your disk only ever grew. Once a day it now trims: recovery copies past the documented ceiling, the short-lived bookkeeping it leaves between tool calls, and its own backups once they are a month old. A report bundle you generated yourself is never touched, at any age. The one thing this can cost you is `expand-ref` on the very oldest folds — the ones already past the ceiling.
- A plan that will destroy something now says WHAT it destroys, and a provisioning run that fails says which task failed. Both survived only as a count before — "1 to destroy", "failed=1" — with the line naming them folded away.

- Fixed: when a long log was folded, an error sitting in the middle of it could be dropped from what the agent was shown — a failed build read as a clean one. Failure lines are kept out of the fold.
- `skeleton` now shows a type's fields and an enum's variants. It used to report that a type existed and nothing about its shape, which sent the reader to open the whole file — the more expensive answer.
- Code samples from documentation pages arrive labelled with their language again, instead of an unlabelled block preceded by a bare word.

- Fixed: in an accessibility snapshot, a name containing a quotation mark — a heading that quotes an error message, an issue title — came back cut at the quote and glued to the element type. Those names are reported whole.
- Fixed: output produced before tokenade was watching — a conversation it was installed into part-way, or one resumed after a long pause — was counted as if tokenade had made it leaner, in a single lump. Only what happens under tokenade is credited now.
- An accessibility snapshot of a page now comes back about two fifths smaller instead of one eighth. A link that carried nothing but its own address is one line rather than two, and a list item holding a single thing is the thing itself.
- Fixed: in an accessibility snapshot, a list item holding several things could come back with its first child swallowing the rest, so two entries read as one nested inside the other. Items are reported the way the page has them.
- Fixed: a line of ordinary numbers — a timestamp followed by two counts — could be masked as if it were a payment card. Numbers in normal output come back as numbers.
- `ip addr` now answers in one line per interface instead of six. It used to cost what it costs to say four facts across six lines and four levels of indentation; the reformulation keeps every address of both families, every hardware address, every real lease attached to the address that holds it, the state, the size limit and any field we do not recognise — and takes about half the tokens, on a laptop as on a server with sixty interfaces.
- A page fetched twice in one session is delivered once, whether it was asked for through the tool or the command line. The second fetch still happens and is still compared in full: only a page that has not changed by a single byte is replaced by a line saying so, with the full text one command away. A page that moved is delivered whole, as before.
- A credential in an MCP tool result is masked wherever the server put it. Only one of the five places a server returns text was being checked, so a secret came back in clear through an embedded resource, through structured output, through a failed tool call and through a resource read. MCP is wired once and then wraps every tool result you receive, so this applied to every server configured. Image and audio payloads are still passed through untouched.
- A credential named by its field is masked even when its value looks like nothing in particular. An access key is forty characters of noise; what makes it a secret is the field it sits in, and in structured output that field is next to the value rather than in the same line of text.
- A session running a large-context model gets a cost column again. A 1M-context session names its model with a suffix no price list carries, so nothing matched and every dollar figure for that session read as zero — which looks like "this cost nothing" rather than "we could not tell". Bedrock and gateway model names are also reduced to something a price list knows, so a model that has no row of its own under those names still gets one.
- A Terraform value containing `/*` is no longer eaten. The block-comment stripper for HCL had no idea what a string was, so a bucket path or a regex holding those two characters swallowed everything up to the next `*/` — or to the end of the file when there was none. Real comments are still removed.
- A private key inside a JSON value, a config blob or a long log no longer reaches you in clear. The masking rule needed the key's closing marker to be present, and long values are shortened before masking runs — so the marker was often gone, the header was replaced, and the key material itself was served. Output that carried `<redacted-private-key>` could still contain the key. Every delivery command is now checked end to end against four credential shapes in seven document shapes.
- Reading a file can no longer cost you more tokens than not reading it through tokenade. When a file's extension already said what it was — which is nearly every file you open — the check that refuses a compaction bigger than its input was skipped. A tokenizer vocabulary came back a quarter larger than the original, an OpenAPI document five percent larger. Files that genuinely compact are unaffected.
- A page snapshot no longer carries a handle for every paragraph, table cell and image on the page. Those handles exist so an agent can click something; on things nothing can click they were pure weight, and they were a sixth of what a snapshot cost after everything else had been squeezed. Every handle an agent can actually act on is still there, including on the elements the page marks as clickable without saying so in their role.
- A file that is not written in English now comes back as its text. Source in any language, SQL, Terraform, protobuf, markdown and web pages all had the same fault: one string literal, one comment marker or one inline tag on a line was enough to replace every non-Latin character on it with garbage — Korean, Japanese, Greek, Cyrillic, accented French, emoji. Nothing said the text had been damaged, so it read as the file. English files were never affected.
- A document that is not written in English is now compacted at all. A single non-Latin character in the wrong place stopped the whole compaction for that file, and a paragraph of real prose that happened to sit next to one badge was thrown away as decoration.
- A blocked page served in a non-Latin language is now recognised as blocked. The check that separates a real page from a "checking your browser" wall measured length in a way that made any Japanese, Chinese, Korean or Russian page read two to three times longer than it is, so those walls were handed back as though they were the site.
- The savings figure tokenade reports is now the savings you actually got. On some shapes the count could not tell whitespace-padded output from a dense blob, so a figure could overstate a reduction by half again, or understate it by as much. Checked against the real token count over every capture we hold — browser snapshots, build logs, command output, source, web pages, compacted output — the reported figure now tracks it to within a couple of points, and the worst single case went from three times off to under a third. Some numbers get smaller as a result. What you saved did not change; what we told you did.
- A page snapshot taken from a browser now costs about 40 % less, measured on real sites rather than a sample we wrote ourselves. It was the single most expensive thing an agent driving a browser sent us, and the least reduced.
- A page snapshot now describes the page's real shape. Elements could come back attached to the wrong parent, so an agent was told a button sat inside a panel it was not in — and acted on that. Every element an agent can click keeps its handle, and every heading on the page survives.
- A link leaving the site is recognisable as leaving the site again. External destinations were rewritten to look like internal paths, so an agent reading a page could not tell where a link actually went.
- Build output from `npm`, `pnpm`, `yarn` and `bun` now compacts by about a third instead of not at all. These logs repeat one sentence per route, per file, per module — never the same line twice, which is all the old fold could see. Every warning, every path and every pairing is still in what you receive; the sentence is simply said once.
- Asking a question of a generated document — a changelog, an operations journal, a ticket export — now costs up to four times less for the same answers. Most of the reply was the same templated sentence re-delivered; the values that differ between the entries are all still there. Ordinary prose is untouched.
- A release can no longer publish internal working documents to the public repository.

The count was reporting the display limit instead, so a search with thousands of hits gave the same number as one with exactly that few — the one place where a truncated answer looks identical to a complete one. Path and outline listings now say when they are only part of the answer.

Repositories kept under your home directory — which is nearly all of them — were treated as your own configuration, so cloning one was enough for its filter to take effect. - A command split across several lines with a trailing backslash now runs exactly as written. The continuation could be handed to the program as a literal argument, so a search continued onto the next line searched for the wrong thing.
- A command you commented out stays commented out. When a shell comment sat before a `&&` or `;`, the disabled half of the line could still run. Commands without comments are unaffected, and a `#` that is part of a URL or a word still is.
- Handing a command's output straight to tokenade by path now works. `tokenade read <(git diff)` and other stream-shaped inputs came back empty, because the format detection consumed the stream before anything could read it. Files are unaffected.
- An input with no end — a device file, an endless pipe — is now refused with an explanation instead of being read until the machine runs out of memory. It was consuming several gigabytes per second until the system killed it.
- Asking what depends on a directory is now an error that says so, instead of a confident "nothing depends on this". Pointing the dependents check at a module folder used to report zero symbols and zero dependents and report success, which is the same answer a genuinely unused file gives.
- Symbol lookups and repository maps now tell you when the list you are reading is only part of the answer, and how many matches there really were. A search that matched thousands of symbols used to show a first slice with nothing to signal the rest existed, so a symbol whose file sorted late looked exactly like a symbol that did not exist. Machine-readable output carries the real total too. Answers that were already complete are unchanged.
- Projects set up before this release now receive corrected project rules instead of keeping the first copy they were given. Two corrections were sitting undelivered, including one about how your commands are intercepted that said the opposite of what actually happens.
- The formats tokenade can read are now stated in full where an agent actually reads them. Rich Text, FictionBook, OpenDocument drawings, macro-enabled and template Office files, and the netpbm image variants all opened before and still do — but nothing said so, so nobody tried them. A capability that is never mentioned is one your agent does not have.
- The rule that a credential never reaches you in clear is now checked against where it sits in a large output, not only against its shape. Folding and truncation cannot expose one by cutting around it.
- A credential typed as a command argument is masked like one written as an assignment. The half of an AWS credential that actually matters was travelling in clear when it was passed on a command line, and so were `--password` and `--client-secret` values. Documentation placeholders and shell variables stay readable.
- Typing a format name as if it were a command now points you straight at the command that handles it. Before, `csv` suggested `ask` and `logs` suggested `login` — a log file answered with a login prompt.
- Naming a path that does not exist is now reported as the error it is, instead of coming back as "nothing found" with a success code. An empty directory still succeeds, because that is a real answer.
- Packing a single file works: naming one file used to be answered with "no files in scope", for a path you had just typed.
- Commands asked for machine-readable output always answer in it, including when the answer is empty. Two of them printed nothing at all, which a program reads as a broken response rather than an empty one.
- A piped image in the netpbm family is recognised by its content, not just its file name, so it no longer arrives as broken text when it comes through a pipe. The rule that no input is ever handed back as its own bytes is now guarded in both directions rather than assumed.
- Piping something that is not text into tokenade now gets you a one-line description of it. An image piped in used to come back as more than twice its own size in broken characters.
- Reading any file that is not text — an archive, a database, a compiled object, a font — now names it instead of printing its bytes, at every size. Small ones used to slip through and arrive as broken characters.

- The project rules tokenade writes no longer tell you to avoid absolute paths for commands. On an agent with hooks installed the two forms are handled identically, and the rule cost you a habit for nothing.
- The advice to fetch or search several things at once now says what it actually buys — one round-trip instead of several, and a context that is never re-sent — rather than promising a smaller reply. The reply is not smaller; the saving is real and sits elsewhere.
- Asking several questions in one call tells you when your commas were read as a single question instead, and what the rule is. The batched form was advertised everywhere; the one condition it has was not.
- Search over a large repository now indexes the same files every time it is rebuilt. On a repository big enough to reach the index ceiling, which files were covered — and therefore what search could find at all — used to vary between rebuilds.
- Cost totals and the per-model breakdown are now identical across runs on identical data, down to the last digit and the ordering of the list.
- The cost figures no longer depend on which run you are looking at. When two models are level in a session, the one used to price it was picked arbitrarily and could differ between runs on identical data.
- When tokenade cannot set aside the full bytes behind a folded result, the reason is now recorded instead of the recovery pointer simply not appearing. A failure you can explain is one that gets fixed.
- A long directory listing costs a third less again: the permission column, identical on nearly every line of a source folder, is stated once instead of repeated — and every line that differs from it, a directory or a symlink or something executable, still shows its own.
- A command that prints nothing now comes back as nothing, instead of a blank line.
- Asking a recovered blob a question that fits every line of it now gets you the answer — the whole thing, folded to its shape and count — instead of being told nothing matched and being left with a raw dump as the only way forward.
- Asking a short document a question it cannot answer no longer costs more than reading it outright: the note that says so is reserved for sources long enough for it to matter.
- Reading a document off disk is no longer counted as a web fetch, so you stop being advised to batch network calls you never made. The advice that does fire now counts in plain English.
- Search results no longer carry the engine's own "searches related to…" and "people also ask" blocks inside a result's description. Those described the query rather than the page, and because they made a description longer they were winning over the clean one when two engines returned the same result.
- The price table behind every savings figure tokenade reports is now pinned bucket by bucket, so a number can no longer drift quietly away from what it claims to measure.
- Savings from batched calls are now valued at the price those tokens are actually billed at, so the totals mean what they say. This lowers the reported figure for that category; nothing about what tokenade saves has changed, only what we claim for it.
- A steer you have already declined comes back less and less often instead of at a fixed rate, and starts fresh after a long enough pause.
- Asking what depends on a file no longer lists modules whose name merely ends the same way. A module called `console_logs` was being reported as a dependent of `logs`.
- Asking what depends on a file now finds callers that reach into it without an import statement, which in most codebases is most of them. Cross-language false hits are excluded, so the list stays one you can act on.
- Asking for one file's outline now returns the whole outline. It was being rationed as though you had asked for eight at once, so on a typical source tree nearly half of all outlines came back cut short, pointing you at the full file read the command exists to avoid. Asking for several files at once costs exactly what it did before.
- Machine-readable output that repeats itself — structured logs, uniform tables — now comes back several times smaller, showing the shape and how many rows had it. When the rows genuinely differ, the previous summary is kept: the shorter answer only wins when it is also the truer one.
- A web search no longer mixes pages that answer your question with pages that merely came up. Sources with nothing to say are held back, and if none of them answer, you are told that plainly instead of being handed openings that look like findings.
- Asking a document a question it cannot answer now says so, instead of returning passages that look like an answer. Questions the source does answer are unaffected.
- The steer that suggests batching your commands now states what an extra turn actually costs, at the price class those tokens are really billed on. It used to quote a figure ten times larger than the stake.
- The suggestion to write your own compactor for a recurring command now only appears when that exact command really has no route of its own, and it names the subcommand rather than the program. It used to point at programs that were already among the best covered in the product.
- Output that says the same thing thousands of times now folds all the way down instead of being cut back to a partial slice. You get the shape plus how many times it occurred, where before you got the first few hundred lines and no idea how many followed.
- When your session hits its context limit, dead weight is pruned right then: file reads the session has since edited, commands it has since re-run — and now the calls that produced them, not only their output. Resuming that session afterwards costs less, and the pruning itself is free because the context is being rebuilt at that moment anyway.
- A long inline script or generated query stops costing you twice. When a session supersedes a call, the call's own text is now reclaimed alongside its output — short commands are left readable, since folding those would cost more than it saves.
- Asking a command for verbose output now reliably gets you every byte of it, and that rule is guarded rather than assumed.
- Repetition is now recognised in build and compile logs too, not just where the numbers happen to stand alone. A file name like `f412.cpp.o` hid its number from the folding, so six hundred near-identical build lines each looked unique and none of them collapsed.
- Any command that does the same thing many times now reports it once. Package installs, database migrations and build steps print one receipt per unit of work; those lines are collapsed to a single line saying how many there were, and anything that is not one of them — every error, every warning — comes through untouched.
- Running a SQL script through a database client reports how many statements went through, and the error that stopped it in full. Every statement used to acknowledge itself in its own line.
- `bundle install` comes back as what changed, not as the list of everything already in place.
- Applying a directory of Kubernetes manifests reports the resources that went in as a count, and anything the server rejected in full. A few hundred confirmations used to arrive whole, with the rejection among them.
- A rejected `git push` is not buried under the server's progress counters any more. The locally-printed counters were folded; the same counters echoed back from the server were not.
- A `pip install` that fails to resolve comes back as the conflict, not the catalogue. One line per package while resolving is most of what a large requirements file prints, and the explanation sat underneath it.
- A failing `docker build` comes back with the reason instead of the log. A build that dies installing packages had its two explanatory lines folded away as noise while nine hundred lines of step outline were kept — the exact inverse. The same output is now a quarter of a kilobyte and says what broke.
- A failing `go test` now tells you why, not just that. The line naming the failure was kept while the line underneath it — the file, the line number, the expected and actual values — was dropped, so the only way to learn anything was to run the tests again.
- A pytest run reports what failed instead of what passed. Its ordinary progress output — one line per file, all distinct — used to fill most of what came back; a 400-file run with a single failure now arrives about fifteen times smaller, with the traceback untouched. A file whose line shows a failure is never folded: that line is the answer.
- When the recovery cache has to make room, it drops what you can get back another way before what you cannot. The limit is still a limit, but the last copy of something is now the last thing sacrificed, not the first one an older timestamp happened to select.
- A block folded out of a session keeps its recoverable copy for as long as the session can be resumed. Ordinary folds still expire after a week — their source is still on your disk — but a block whose bytes were replaced has no other copy, and losing it left a pointer to nothing.
- A folded block can no longer lose its only copy. The recovery pointer left in a compacted session is now protected from cache eviction like every other, so `expand-ref` still works after a long session.
- A row of ordinary numbers is no longer mistaken for a payment card. A table of counts or measurements could come back with two of its rows masked, which silently changed the data you were reading. Real card numbers are still masked.
- Reading code and documentation no longer loses the line you were reading. Any assignment whose left side ended in `_token`, `_key` or `_secret` had its right side masked as though it were a credential — a page of Django docs came back saying `primary_key=<redacted>`, and source came back with the call gone. Environment variables still lose their values.
- The same protection now looks at what it is about to hide. A field type, a function call or a namespaced path on the right of `password`, `token`, `secret` or `key` is code, and code is left intact — `let secret = derive(seed)` and `password: String` come back whole. Anything that could actually be a credential is still masked.
- The same search now returns the same page every time, on web content and on saved results pages too.
- An MCP tool result that folded hard now carries a way back to the full payload. These calls are the ones you often cannot simply repeat — a paginated fetch, a search over data that has moved on, a report about a change already made — so the folded copy used to be the only one. The result itself is unchanged; the pointer just rides along.
- Piping content in — a log, a JSON dump, a saved results page, an accessibility tree — no longer costs you the original. These fold the hardest of anything we handle, sometimes to a thousandth of the input, and there is no file to go back to; now there is a pointer that returns every byte. Reading a named file is unchanged: the path you typed is already the way back.
- A release can no longer take a platform away. If a build had covered fewer platforms than the release already online, the users left out would have lost both the new version and the one they were running, because the old files are cleared once the new ones are up.
- A release can no longer go out with only some platforms built. The published package promises a binary for every supported platform, and if one had been skipped, installing on that platform would simply have failed — for those users only, with nothing in the release reporting it.
- A release can no longer publish documentation older than what is already online. The public page could be replaced by a stale copy without anything reporting it.
- Asking a question of a folded search result or log now answers with the matching lines, near the top, for a fraction of what it used to return. The old answer buried the one line you wanted under sixty lines of its neighbours — which, in a search result, belong to unrelated files.
- Recovering a folded blob now suggests the way in that actually fits it. Over a search result or a log, asking a question in words retrieves poorly — neighbouring lines are unrelated, so there is no passage to find — and matching a pattern is both exact and cheaper. Over prose it stays the other way round.
- A fold that told you how to recover it now hands you what you need to do so. Some views named the recovery command without ever printing the reference it asks for, so the instruction pointed at nothing — and those were precisely the views that went without one.
- Whatever a command's output loses to folding can now be recovered. Until now the pointer appeared only when what remained was still large; a search folded from 14 000 matches down to two hundred lines left no way back to the rest but re-running the command — which is not always possible, and never free.
- A recursive `grep` over a whole tree now says where the matches are — how many per file, most-hit first — before showing the excerpt. A few thousand hits used to arrive as two hundred arbitrary lines.
- `grep -r pattern dir/` without `-n` gets the same repeated-path folding as the `-n` form. That is the shape agents type most, and it was the one shape being missed.
- Listing a repository — `git ls-files`, `ls-tree`, `rev-list`, `worktree`, `submodule`, `lfs ls-files` — now comes back as a directory summary instead of thousands of paths. On a mid-size repo that is one of the largest single outputs an agent ever reads.
- Reading a big slice of a source file with `sed -n`, `head` or `tail` now costs what the same read through `Read` costs. Short slices are left byte-for-byte alone, because those are edit targets.
- A command run under `timeout`, `nice`, `stdbuf` or a similar wrapper is compacted by the tool it actually runs. `timeout 300 cargo test` was being treated as a program named `300`, so it fell back to generic compaction and its savings were filed under the wrong name.
- Asking several questions in one call now says so when the batch is longer than one call can answer. Previously the reply came back numbered and looked complete, so a question that was never searched for was indistinguishable from one the document had no answer to.
- `impact` now lists what a file declares in the order the file declares it. Only the first names of each kind are shown, and alphabetical order handed that space to whatever sorted first — on a test-heavy source file that meant a list of unit tests with the entire public interface hidden behind the overflow count.
- `query` no longer claims a file declares a trait it merely implements. Asking where `Drop`, `Default` or `Display` is defined used to return a list of every file that implements it, with the real declaration nowhere in sight. Implementations are now reported under the type they extend, and shown as such.
- Improvements to symbol extraction now reach repositories you already indexed. A cached index was only ever refreshed for files whose contents changed, so a file nobody touched kept the symbols it was first parsed with — indefinitely, across upgrades.
- `skeleton` no longer spends most of its output on a file's test module. On a well-tested source file the tests were the majority of the signatures returned, so the question "what does this file offer?" came back answered mostly by its proofs. The module still appears, with the folded line count, and tests remain findable by name.
- `semantic` results now carry a score that actually tells them apart. Every result of every query used to come back at the same value, so the number said nothing about which match was strong — and a query that matched almost nothing looked as certain as one that matched exactly. Results are no longer labelled as reranked by a stage that does no reranking.
- `map` stays a cheap overview on a large repository. Its directory listing had no upper bound, so on a big codebase the command meant to save you from reading files cost more than reading several of them — and most of what you paid for were directories holding a single file. The densest directories are kept, the count of what was trimmed is stated, and `--json` still returns everything. Small repositories are unchanged.
- `impact` answers "what does this affect?" without printing every last leaf. On a widely-imported module the reply ran to hundreds of paths, well past the point anyone reads, and the useful part was already at the top. The most-affected files are listed, the number left out is stated, the count still reports the true total, and `--json` still returns the complete list.
- The suggestion to write your own compactor for a recurring command now only appears when there is something left to gain. It was triggered by how much output a command produced, not by how much still reached the model afterwards, so it fired on commands tokenade had already reduced to almost nothing — and advice that arrives when it is not warranted stops being read when it is.
- `map` now says how many files its ranked list left out. The heading read as though those were the files that mattered in the repository, when it was showing a fixed handful of the densest ones out of possibly thousands.
- You can now ask far more questions in a single `--prompt` call. The ceiling was low enough that a deliberate batch hit it, which is the opposite of what batching is for.
- YAML that is not a Kubernetes manifest keeps its own fields. A list of names that are pure bookkeeping under kubectl — `uid`, `creationTimestamp`, `resourceVersion` and friends — was being applied to every YAML file, so an ordinary application config lost real values.
- `semantic --output-mode count` now answers something about your repository instead of repeating the size of its own result window, which was the same number for every query ever asked. A `--limit` flag sets how deep the search goes, and a count that fills the search's candidate pool is marked as a floor rather than passed off as a total.
- `wrap` can keep stdout and stderr apart with `--split-streams`. By default the two are merged, which is what an agent wants; a script that redirects output was getting error text written into its data file.
- On Windows, `map` now shows your repository's directories instead of a single line for the whole tree. Paths were stored with the platform separator while everything that reads them expects `/`, so every file was grouped under one directory.

## 0.7.7

- **Full savings across sub-agents.** When your agent spawns sub-agents,
  each one gets its own accurate savings context and keeps compacting at
  full strength throughout.
- **Test failures always reach you.** Summary and tally lines from test
  runners (the passed/failed counts printed at the end of a run) are
  preserved verbatim in every compaction.
- **More secrets stay out of transcripts.** Redaction now covers more
  credential shapes across command lines, headers, config files and key
  material.
- **Self-monitoring got teeth.** `tokenade doctor` now flags savings
  features that stopped firing on your machine, and warns loudly if
  another tool wipes the agent-hook wiring.
- **Sturdier detection on unusual output.** Several format detectors are
  more conservative on mixed or ambiguous content — structured rewrites
  only happen when the whole body agrees, so odd documents pass through
  untouched.
- **One honest headline number.** Dashboards (terminal, HTML, tokenade.net)
  now headline a single "tokens" figure weighted at real price ratios —
  output tokens count for what they actually cost relative to input and
  cache reads. A legend under the number explains the weighting; the raw
  split and per-model $ stay visible.
- **Dollar values are the real thing.** Every saved token is now valued at
  the actual price of the model that produced it — across all the models
  you've used, not a single blended guess — and the same figure shows up
  everywhere: your statusline, the terminal and web dashboards, and your
  account page. Works for every agent whose model usage Tokenade can read.
- **Live savings in your status bar.** Claude Code's and Qwen Code's
  statusline now shows your current session's savings as they happen — and
  if you already have a custom statusline, tokenade keeps your text and
  appends its ticker to the same line. Opt out anytime.
- **T3 Code supported.** Sessions driven through T3 Code inherit the
  full Tokenade coverage of the agents it fronts (Claude Code hooks load
  natively); the installer recognizes T3 and wires accordingly.
- **Repeat-poll costs drop.** Re-running the same status/poll command in a
  loop gets progressively cheaper, and identical images pasted twice are
  served from cache.
- **Hermes support.** Tokenade now compacts large tool results inside
  NousResearch Hermes and reports Hermes usage on your dashboard.
- **More agents covered.** Pi, OpenCode, OpenClaw and Kilo now get their
  large tool results compacted the same way Claude Code already did.
- **Repetitive logs collapse.** Long, near-identical log output (the same
  line pattern repeated hundreds of times) now folds to a compact summary
  while every distinct line — errors included — is kept verbatim.
- **Rock-solid install and update.** Installing or uninstalling preserves
  your existing agent configs in every case, updates are health-checked
  before they replace the running binary, and the npm install path now
  verifies a cryptographic signature.
- **Snappier hooks.** Per-prompt and per-edit overhead was removed, so
  Tokenade stays invisible on the hot path even in long sessions.
- **Verifiable accounting.** The savings figure is a true net — Tokenade
  counts its own footprint against it — and lifetime totals carry over
  intact when upgrading from any earlier version. A new `tokenade
  audit-gains` command lets you check the books yourself.

## 0.7.6

- **Works on Debian 12 and older distros again.** The Linux binary no longer
  requires a recent glibc — anything from Debian 11 / Ubuntu 20.04 onward runs.
- **Error lines can no longer be lost.** In mixed command output, an error
  message that lands in the middle of tabular or structured noise is now
  always preserved verbatim, never summarized away.
- **Unchanged commands stop re-billing.** Re-running a read-only command
  (git status, ls, …) whose result provably didn't change now costs a few
  dozen tokens instead of a full re-execution and re-delivery.
- **Recovery after context compaction.** When the agent's context gets
  compacted, Tokenade re-offers the freshest folded outputs so nothing has
  to be re-run to get back to work.
- **Savings are now priced at your real models.** The dashboard and
  tokenade.net price every saved token at the rates of the model that was
  actually in use — not a flat estimate.
- **Cleaner web pages.** Fetched pages drop navigation, share bars, cookie
  banners and related-links clutter more aggressively while keeping the
  article intact — noticeably fewer tokens per page.
- **OpenTofu support.** `tofu` output is compacted like `terraform`.
- **Hardened install.** `tokenade doctor` now verifies the installed hooks
  haven't been tampered with, and project-local filters require a one-time
  trust confirmation before they run.
- Fewer repeated-output loops, better batching guidance, and assorted
  robustness fixes.

## 0.7.5

- **Re-reading a file you just edited is now dramatically cheaper.** Agents
  that iterate on the same files (edit, re-read, edit again) see only what
  changed instead of paying for the whole file every time — on big files this
  routinely saves over 90% of the re-read.
- **Writes get smarter guidance.** When an agent is about to rewrite a whole
  existing file for a small change, Tokenade steers it toward a targeted edit —
  output tokens are the most expensive kind, and this trims exactly those.
- **Better on Windows.** PowerShell file dumps and searches (`Get-Content`,
  `Select-String` and their aliases) now get the same compaction as their
  Unix counterparts.
- **Remote work is covered.** Output from commands run inside containers
  (`docker exec`, `docker compose exec`, `kubectl exec`) is now compacted
  like the same command run locally.
- **Screenshots from connected tools are downscaled** before they reach your
  agent — full resolution stays recoverable on request.
- **Web pages fetch more reliably**, with an automatic second attempt when a
  site refuses the first one.
- **Large code files stay fully navigable.** Structural views of big source
  files now always list every symbol.
- **Your stats now tell one story everywhere.** The terminal dashboard, the
  local web dashboard and tokenade.net now count savings the same way, split
  by token type (input / cache / output) with a consistent dollar value —
  including netting out Tokenade's own small prompt cost.
- Dozens of robustness fixes across compactors, hooks and installers, backed
  by a new always-on quality harness.
