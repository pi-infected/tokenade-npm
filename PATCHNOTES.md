# Tokenade — what's new

## 1.1.9

- A source file that came back without its comments now says so, says how many, and says whether your line numbers still hold. Reading source through the shell — `cat mod.py`, `sed -n '1,600p' app.ts`, `head`, `tail` — strips comments when the slice is big enough to be a browse. Every other stripper in tokenade announces itself (`[tokenade:toml]`, `[tokenade:ini]`, hcl, bazel, proto, sql, cmake); the SOURCE path, which is the busy one, returned the stripped text bare. Worse than silent: a comment line is replaced by an EMPTY line, so the file comes back with the right number of lines and a blank where the explanation was — it does not read as compacted, it reads as a file that has no comments. REPRODUCED 2026-09-05 on a 600-line Python file: all 200 comment lines gone, no banner at all. And measured on this machine's transcripts, **5 352 source reads go through a shell reader** (`sed` 3 532, `cat` 1 038, `head` 427, `tail` 355) — the field quote that started this is an agent reasoning about its own repo: *"Bon, le fichier est correct (le sed précédent affichait une version compactée par tokenade)"*, having first concluded the file was wrong. It now reads `[tokenade:py] 200 comment line(s) stripped; the file on disk is unchanged (line numbers unchanged)`, and where blank runs collapse instead, `399 line(s) of blank runs collapsed … (line numbers have SHIFTED)`. Both halves are measured rather than inferred: the count, because blanking keeps the line count and the generic wording would have called 200 removed lines "inline comments trimmed"; and the anchors, because a reader told only that comments were stripped has to assume its `sed -n '410,420p'` moved — which is false half the time. A file with nothing to strip is untouched and unbannered, and a strip too small to pay for its own banner is served whole as before.
- A subagent's report keeps its conclusion when a resume masks it. Resuming a session re-bills its whole history, so tokenade masks the biggest stale blocks in place and leaves an exact pointer. Every other thing a transcript holds names something you can have again — a file is on disk, a command re-runs, a page re-fetches — but a `Task`/`Agent` report is the distilled output of a run that will not happen the same way twice, and replacing it with a bare hash leaves a pointer where a conclusion was. MEASURED 2026-09-05 across this machine's transcripts: **6 subagent reports were masked whole**, at 2 173, 2 241, 2 538 and 2 676 tokens among them — all just over the 2 000-token bar, so it was the generic size gate treating a deliverable like any other output. The opening 400 characters now stay, the bulk still goes, and the pointer is unchanged: **95% of the saving retained** on those six. An ordinary result does not buy the head — it is only paid for where re-running is impossible.
- The "`cat` does not satisfy Edit's Read-first precondition" heads-up now sees the command behind a `cd`. `cat a.ts b.ts` followed by an Edit of either file costs the content twice — Edit refuses with `File has not been read yet`, and each file has to be Read anyway — so tokenade says so once per session. It asked whether the FIRST token was `cat`, which made `cd repo && cat a.ts b.ts` invisible: the same command, one word earlier. MEASURED 2026-09-05 across this machine's transcripts: of 118 multi-source `cat` clauses, **91 were seen and 27 missed, 20 of them behind a leading `cd`**. It reads the working clause now, the same way the router and the compactor-gap suggestion already do. The token count moved with it, which closes the other half: counting across the whole line let a later `grep b.ts` push a single-file `cat` over the two-file bar and warn about a pattern that was not there.
- Disabling the hook for a command tokenade never touches is now said once, instead of costing you a bypass in silence. `vim`, `less`, `man`, `ssh`, `scp`, `rsync`, `sudo`, `sshpass`, `tmux`, `watch` and the rest of that family are on a pass-through list: they are never wrapped and their output is never compacted. Nor is a `tokenade …` command, which the hook skips so it does not wrap itself. MEASURED 2026-09-05 across this machine's transcripts: of **556 runs carrying `TOKENADE_HOOK_DISABLED=1` or `TOKENADE_FORCE_BYPASS=1`, 258 (46%) named one of them** — `sudo` 148 times, `sshpass` 93, `tokenade` 17. The variable did nothing, and the run was still booked as a lost saving, so the dashboard carried 258 losses that never happened. The habit is worth understanding: it starts on the one command where being careful is right (a `sudo` askpass flow, an `sshpass` login) and then spreads — 244 of those came from a single session, and 517 of the 556 were written before any fold had happened. The first such command in a session now comes back with one sentence naming the program and saying the variable changed nothing. A bypass of a command tokenade really does fold is untouched, and so is a pass-through command run without the variable.
- "You've run this exact command 3× — re-running won't change the result" no longer says that about a poll. The loop guard counts identical commands within a session and steers you off the third one, and it only ever compared the command's INPUT. A watcher does not work that way: a build log tailed every minute, a health probe, a test suite writing to a file — same command, different answer every time. MEASURED 2026-09-05 across this machine's transcripts: the steer fired 198 times, and of the 50 whose command could be matched back to its own runs, **5 were on a command whose outputs all differed** — `timeout 900 python3 scripts/watch.py … | tail -10`, seven runs and six distinct answers, and a `curl` health check. It lands in PreToolUse, before the command runs, so a false one argues you out of the only thing that was working. The counter is now cleared when a re-run's raw output differs from the previous run's: an Edit/Write already restarted it (edit→test→edit is iteration, not a loop), and this is the same idea for state the session does not own. A command that really is stuck — same input, same bytes, turn after turn — still gets the steer at the third run, unchanged.
- `expand-ref --grep` takes a regex, and a flag written before the pattern is read where you meant it. Two silent wrong answers on the one command reached only AFTER a fold already took the bytes away, where `0 matching line(s)` reads as "the content is not there" and the search stops. The flag is called `--grep` and it was a plain substring test: MEASURED 2026-09-05 across this machine's transcripts, **38 of 128 patterns (30%) were regex-shaped** — `OSCILLE|ligne\(s\)|suspect`, `ok |FAIL|error|warning`, `\[8\]` — and not one of them could match. Separately, **12 of 261 `expand-ref` calls put `-i` between `--grep` and its pattern** (63 occurrences): the flag became the pattern, the pattern fell through to the hash reader, and the answer was `nothing matches "-i"` followed by `'poll' is not a ref hash` over a stash whose every line held the word. A pattern is now matched as a regex OR verbatim — a union, so nothing that used to match stops matching, and `ligne(s)` still finds the parentheses it names. `-i` and `--raw` written before a pattern are applied as the flags they are, on both halves of the parse; `--grep -- -i` still buys a pattern that is literally `-i`.
- The "write a compactor for this" nudge no longer names things nothing can compact. When a program runs repeatedly and only ever gets generic compaction, tokenade suggests `tokenade add-compactor`. It took the name from the first token of the command, and an unparsable chain — a heredoc, a `for` body, a `;`-joined script — leaves something else there. MEASURED 2026-09-05 across this machine's transcripts: of 268 nudges delivered, **94 named something that could never have a compactor**, and 17 of the 22 distinct names were bare integers — `300`, `600`, `1700` — the argument of a `sleep` or a `timeout` read as the program. `echo` accounted for 14 of them, most recently on 2026-08-29: `echo` prints back exactly what you typed, so there is nothing to cut. The counters on this machine confirmed it from the other side — `SI.nudged` had already fired for a two-letter string that is not a program, beside `file_search.rs` and `echo`. Two rules now: a scene-setting token (`echo`, `printf`, `sleep`) is never named, and neither is a name that does not resolve to something runnable. A real program tokenade does not compact is still named, exactly as before.
- A repeated `cat <file>` is answered with the file, not with a stash hash. When a command's output is byte-identical to its previous run, tokenade answers the repeat instead of re-serving it — and the way back it named was always `tokenade expand-ref <hash>`, which returns what was DELIVERED (already compacted), not the file. For a file read that is the wrong pointer twice over: a `cat` is not a poll, it is you looking at something you need now, and the file is still on disk where `Read` takes offset/limit and re-reading an unchanged path costs a diff instead of the bytes. MEASURED 2026-09-05 across this machine's transcripts: of 105 dedup answers, **50 were a plain single-file read and 31 of those (62%) were followed within three turns by an `expand-ref` pulling the content back** — 72 488 tokens and 31 turns spent undoing the fold, at a 3 019-token median. The answer now reads `<path> has not changed since that run — Read <path> (offset/limit) for the bytes`, with the stash pointer kept beside it for what was delivered. Both answer shapes say it, including the `still unchanged (N consecutive identical runs)` one-liner, which carried no way back at all beyond the hash. A command that reads no single nameable file is unchanged: there is no path to point at, and claiming one would be a statement about bytes that never came from a file.
- A fetched page smaller than the note explaining it away is now served whole. `WebFetch` on a large page is answered with the passages matching your prompt plus a paragraph saying the page was withheld and an `expand-ref` line telling you how to get the rest — about 150 tokens of machinery. Below that size the machinery costs more than the page, and nothing was checking: MEASURED 2026-09-05 across this machine's transcripts, of 225 scoped deliveries **26 (11.6%) distilled to no more than their own excerpt plus that explanation**, the smallest to 122 tokens — a page handed back in fragments behind a banner bigger than the page, with a recovery command for bytes that would have fitted inline. The whole-page delivery already existed and already had this test (`tokenade web` serves any page under ~4 000 tokens intact); the hook path just never asked. Those 26 now arrive complete, 9 564 tokens cheaper in aggregate. A page of ordinary size is scoped exactly as before, and a page over the inline cap is always scoped — there the alternative is not serving it whole, it is overflowing your context. The banner also stopped claiming every page is "too large for the native fetch": above the cap that is the reason, below it the reason is that the passages are cheaper, and it now says whichever is true.
- `expand-ref --grep` that matches nothing now shows you what IS in there. It answered `0 matching line(s) of 24 total` and stopped — on the RECOVERY command, reached only after a fold already took the bytes away, so the caller had no way to fix the pattern except to spend another turn dumping the hash. MEASURED 2026-09-05 across this machine's transcripts: of 38 `--grep` answers, **22 matched nothing**, and in every case sampled the very next call was another `expand-ref` on the SAME hash (`| tail -26`, or `--grep "."`) purely to find out what it held; six of the 22 held fewer than 60 lines in total, which is less than the round trip they forced. A miss now prints the first 12 lines beside the count, and names `--prompt "q1, q2"` as the cheaper way to ask. It goes to stderr, so `expand-ref --grep X | wc -l` still answers 0, and a grep that DOES match is unchanged. The existing case-fold hint still wins when it fires: there the caller already has its next move.
- "Unchanged since the last run" is now a claim about your command, not about the fold. When the same command is re-run, tokenade can answer the poll instead of re-serving the output — `unchanged — byte-identical output to the previous run of this command`. It decided that by comparing the two COMPACTED strings, and a fold that drops a middle makes two different outputs deliver identically. REPRODUCED 2026-09-05: a 400-line file, ONE line rewritten inside the middle a large `cat` elides, and the second run answered **`unchanged — byte-identical output to the previous run`**. An agent polling that file is told nothing moved, and it did. The poll pointer is keyed on the command's raw bytes now, so the sentence is checked against what it says. A genuinely unchanged re-run still answers the poll, exactly as before, and the near-identical "this run changed nothing" nudge still fires on a run that varies only by timestamps. The middle of a big `cat` is still elided on purpose; what changed is that tokenade no longer asserts it was not.
- A truncated `cat` says how much it dropped, and every command it names actually runs. The banner quoted two constants — "showing first 150/last 50 lines" — of a total it never gave, so you could not tell whether 3 lines or 3 000 were missing, nor pick the `offset` for the `Read` it was telling you to do; and the head is adaptive, so those constants were not what happened either. Then it advertised `skeleton path="<file>"`, which the CLI answers **`No such file or directory`** — that argument shape belongs to the MCP tool, not to the command. MEASURED 2026-09-05 over this machine's transcripts: 23 of these were delivered at a 2.9 KB median and **not one was ever asked a question**, while the agent pulled the bytes back 6 times and went around the hook 3 times — a fold nobody questions is a fold whose banner never suggested a question. It now reads `<file>: 267 lines ≈4053 tokens, 59 line(s) elided from the middle`, and offers `tokenade read <file> --prompt "q1, q2"` first (the cheapest path the shipped guidance names), then `tokenade skeleton <file>` in the spelling the CLI takes, then `Read` with offset/limit.
- `cd <dir>; <command>` is now compacted as the command, not as `cd`. The leading `cd` is scene-setting, and it was being read as the program the output belonged to — so `cd repo; cargo test` reached the generic archetype instead of the cargo-test compactor, and the banner said `[tokenade:cd]`, a label naming nothing you ran. MEASURED 2026-09-05 across this machine's 549 non-tokenade transcripts: **22 852 commands had their program read as `cd`**, and the real one is `grep` 3 938 times, `python3` 3 978, `sed` 2 425, `cat` 1 162, `cargo` 780, `sqlite3` 758 — every one of them a compactor that never ran. Of the 45 results that came back banded `[tokenade:cd]`, at a 3.2 KB median, **not one was ever asked a question** (`expand-ref --prompt`, the cheap path) while the agent went around them 12 times: a fold nobody can question is a fold that removed the thing itself. The chain-aware path already skipped a leading `cd` when the command could be split; a heredoc makes it unsplittable, which is exactly the shape this hits. 98% of those 22 852 now name their real program. A bare `cd /somewhere` is still `cd`, and `cd x | tee` still is not a clause boundary.
- A repeated COMMAND now answers the question the repeat asked. The commands agents repeat are polls — `tail -30 build.log`, `sleep 90; tail -16 …`, `until [ -s … ]` — and tokenade answered them with a hash and a size: `§ref:<hash>§ (~452 tokens / 1809 bytes, identical to a prior call)`. Nothing about whether the job moved. The same product already answers the SAME situation better one route over: `exec-dedup` gives the age, the exit code and the last five lines. MEASURED 2026-09-05 across this machine's transcripts: of 208 dedup-folded results delivered to an agent, **14 runs were followed by `tokenade raw` or `TOKENADE_HOOK_DISABLED=1` on the same command** — the agent spending a turn, and the bypass, to read bytes it had just been refused. The pointer now carries the last lines of what it replaced, under the same margin the fold has always had to clear (twice what it emits). On the same corpus, **194 of 194 folds on that route are large enough to carry the tail and still pay**. A repeated Read is unchanged: its floor was measured and settled on its own terms, the file is still on disk to name, and a guard pins that marker's size.
- A tool call the resume compactor shrank still says what it was. Resuming a session re-bills its whole history, so tokenade masks the biggest stale blocks in place and leaves a recovery pointer. For a `tool_use`, that masking replaced the WHOLE value — and a superseded call's result is already gone, so what was attempted is the only thing the block still carried. MEASURED 2026-09-05 across 805 local transcripts: **540 masked values landed in `input.command`**, the smallest at 90 tokens, several of them re-encountered by the agent more than once. `{"command":"[tokenade:elided 90 tokens …]"}` is a readable JSON key in front of a call nobody can identify, and an agent that cannot read what it ran runs it again. The head of the value now stays — the first line, up to 180 characters — and only the bulk after it leaves: `cd /srv/app && python3 - <<'PY'` still reads as itself while the 6 KB heredoc behind it goes. Priced on the same corpus: **92.2% of the saving retained**, 58 295 of 58 357 masked values keep a legible head, and 1 839 short commands (3.1%) are no longer touched at all because keeping their head leaves nothing worth masking.
- The status-line ticker takes its own line when it is sharing the line with a command you already had, and the rotating ask has its own OFF switch. Two reports, one line. Wrapping another tool's KPI status line ran both into one long line that the host then wrapped wherever it liked; the ticker now goes on the next line, which the hosts already support (Copilot's runner splits our output on newlines and pads each, Cursor renders into an unconstrained box). When the left part is our OWN `model · dir` there is nothing competing for the line and it stays one line. And the rotating ask — star us / refer a friend / leave a review — is now `tokenade statusline promos off`, separate from `tokenade statusline off`: being rid of the ask used to mean throwing away the savings figures the ticker exists for. The ask itself now ends in a `✕` linking to the page that names that command. It is a link, not a button: a status line is stdout and there is no click channel back into the process, so the cross points at the instruction rather than pretending to be one.
- A rule file you keep in sync with a symlink no longer re-runs the scaffold on every session. `CLAUDE.md` symlinked to `AGENTS.md` is ONE file under two names, and the pass walked the names: it read the same file twice, computed two different blocks for it (`CLAUDE.md` omits the subagent note), and the repo-symlink guard then refused the link half. That refusal is correct and stays — a cloned repo must not be able to point `CLAUDE.md` at a file on your machine for us to write 4 KB into — but it was counted as a write FAILURE, so `.tokenade/scaffold.flag` was never stamped and the whole pass re-ran on every session forever. Names are now resolved to the files they name: a link that stays inside the project is followed and written ONCE, carrying the note both halves need; a link that leaves the project is still refused, and is now SAID — `CLAUDE.md left alone (links outside the project — no rules written)` — instead of silently leaving a rule file with no rules in it. Measured on all four link shapes: one block per file, the link still a link, and the second pass a no-op.
- `tokenade dashboard` opens the dashboard instead of also printing it. The bare command rendered the full colour terminal report to stdout, THEN wrote the web page, THEN opened it — so the browser tab arrived under a screenful of text nobody had asked for, and the same figures were aggregated and formatted twice in one run. It now writes `~/.tokenade/dashboard.html`, hands it to your browser, and prints one line: the URL. The terminal report is the fallback and appears exactly where the page cannot be put in front of you — a headless session (SSH, or no X11/Wayland display), or a browser launcher that refused — and `--text` asks for it on purpose. `--html`, `--json`, `--no-open` and `--watch` are unchanged. `--days` windows the terminal report, so on the default run — which opens the page, and the page has its own period selector — it is now refused with a pointer at `--text` instead of parsing and doing nothing.
- The dashboard's period selector now drives every panel on the page. It did not. Each panel derived its own cutoff from the generation stamp, and two of them — per-model consumption and "outside tokenade" — sliced their per-day series against the MEASURED ledger's day list, so a day on which your agents worked and tokenade recorded no operation did not exist for them at all. A third set of figures ignored the control by construction and said nothing about it. Switching 7d/30d/90d moved some numbers and froze others, with nothing on screen saying which was which. There is one window now, one predicate applying it, and every panel prints the dates it covers. Measured on this machine's ledger, 7 days against all history: **$79.24 → $2 049**, 23.33M → 629.78M tokens saved, 970 → 72 424 operations, 17.4k → 198.0k secrets redacted, compaction 90% → 93%, share of the agent bill 69.2% → 86.6%. The activity map is 26 weeks by definition and now says "lifetime" on its own head rather than quietly ignoring the range. The chart also draws the days on which nothing happened: a sparse ledger — this one holds 29 days of rows spread over three months — drew the same handful of bars at every range, which is most of why the selector looked broken.
- The dashboard page was rebuilt. One headline (what the selected window saved, in dollars) with a compaction gauge and the share of your agent bill beside it, a strip of six figures under it, one chart, and the six breakdown tables folded into a single tabbed panel instead of six stacked ones. Every panel carries a chip naming the window it is showing, and an empty range says so and offers the full history instead of rendering a page of zeroes. Light and dark both. Two controls are gone: the `$ / Mtok input` box, which had stopped feeding any figure on the page, and the EN/FR toggle — the page follows your browser's language now, with no remembered preference to disagree with it.
- `tokenade dashboard` is about three and a half times faster. Six separate walks of the local agent transcripts — the bypass totals, the per-day tool tokens, the cache-write series, the per-model panel, the model attributor behind the dollar figure, and the cross-agent output-lean estimate — each opened every session file the others had just finished reading. Measured on this machine's 1.3 GB of Claude Code transcripts: the page took **1.94 s, of which 1.4 s was those walks**, and takes 0.97 s now that they are one walk whose result they share; the default run also stopped rendering the terminal report first, which cost a further 1.68 s on the same corpus. Nothing about the numbers changed — the readers it replaces are still there, and a test demands the fused pass agree with every one of them, dedup scope by dedup scope.
- An encoded blob is no longer described as a directory listing. Base64 uses `/` as one of its 64 symbols, so its lines cleared every exclusion the archive detector had accumulated around `contains('/')` — the last whitespace token contains a slash, and that was the whole test. Measured on `base64` of a 200 KB file: 3 509 lines delivered as **`[tokenade:archive] plain-listing — 3509 entries`** followed by "(3509 entries grouped by directory — pass a path or glob to the listing to see individual entries)". Entries that are not entries, directories that do not exist, and advice that means nothing. A listing now has to actually GROUP — distinct first segments must be at most half the entries, which is what the renderer promises when it says "grouped by directory". Measured the same day: `find` 0.001, `du -a` 0.000, `git ls-files` 0.005, `ls -lR` 0.011, absolute paths under different trees 0.002, a mixed rsync listing 0.005 — against 0.969 for base64. Listings of a handful of entries are judged by nothing and served as before. The same rule now holds on both routes: the content route asked the question on a truncated head, where the bar could never bind, and answered `kind=ls.txt` for the same blob.
- `tokenade exec` says when a large bash script ate the data you piped in. A `bash`/`sh` script is handed to the interpreter ON stdin, so above 64 KiB — where it can no longer travel as an argument instead — it consumes the very channel the caller's data arrived on, and the script runs against an empty stdin. Measured on a 70 KB script ending in `wc -l` fed 500 rows: **`rows seen: 0`, empty stderr, exit 0** — an answer computed on no input, indistinguishable from a correct answer on empty input. The size ceiling's own note said this case was "stated rather than silently mishandled"; it was stated in `--help` and nowhere else. It is now said at the moment it happens, with what to do instead. A script small enough to travel as an argument still receives the data and says nothing, and `< /dev/null` — where there was nothing to lose — says nothing either. Python, node, ruby, jq and awk take their script as an argument and were never affected.
- A `diff` is folded by the parser that keeps its changes, not by a head+tail slice. `diff`, `diff -u` and `diff -r` each handed their output to a generic archetype that keeps the first 50 lines and the last 5 — and a diff's changed lines are the only thing it carries. Measured on a 1,610-line `diff -u` comparing two 1,200-host inventory reports: **27 of the 810 changed lines came back**, under a banner reading `[tokenade:diff] 1610 line(s)`, which is the size of the input and says nothing about the 783 changes dropped. An agent diffing expected against actual read 27 differences and had no way to know there were 810. A unified diff now reaches the unified-diff compactor, and where the shape fold still wins on size it claims every line it folded with a `[×N lines]` count: same input, 1,605 of 1,611 lines accounted for, 97.1% smaller. A short diff still passes through untouched, and a normal (`<`/`>`) or context diff keeps the archetype.
- `tokenade skeleton --budget N` on a single file no longer claims the file is shown in full when it is not. The flag chooses WHICH targets are shown, so with one target it cannot bind — that much was already said. But the note went on to state "the one target you asked for is always shown in full", printed one line under that file's own footer reading `truncated at ~2500 tokens; +8 more symbol(s) hidden`. Two different bounds, and the message claimed the one it does not control: the per-file skeleton ceiling. It now names whichever applies — the footer above and how to reach a hidden symbol when the file was cut, "there is nothing to withhold" when it was not.
- `tokenade web <page> --prompt "…"` names the way back to what it did not show. The page is converted, folded and stashed, and the pointer to that stash is written on the answer — then a question replaced the whole answer with the passages that matched, pointer included. Measured on a 59,552-byte page, the same bytes and the same six questions: through `read --prompt` the reply ended on `tokenade expand-ref <hash>`, through `web --prompt` it ended on the last line of the answer, with **13,544 tokens folded away and nothing naming a way back**. Worst on the documented pipe form (`curl -s <url> | tokenade web -`), where the bytes came off the network and are gone from the shell — the stash file was written either way and only its name was thrown away. A page small enough to be served whole is unchanged: there is nothing folded, so no pointer is invented. A page that quotes a `[stashed: …]` line of ours in its own body still gets the live pointer, not the quoted one.
- A custom compactor's TOML is checked field by field, and its answer is honoured. Two ways it was neither. A misspelled key installed cleanly and did nothing: `strip_line_matching` (singular) folded nothing, and `expect` instead of `expect_contains` left the author's self-test — the gate the install is supposed to run — silently absent; an unknown field is now a refusal that names it, and a `[[tests]]` case with no assertion is refused too. And the answer a filter produced could be thrown away for a fold of the RAW bytes: measured on a filter that strips a test runner's download and cache chatter, the delivered answer was **6,852 bytes with every stripped line back in**, against the filter's own 17,958 with none of them. A filter an operator installed is an instruction, not a candidate — the repetition fold now runs on its answer, which on the same run gives 506 bytes with the chatter gone and both failures intact.
- In a custom compactor's TOML, `^` and `$` mean the start and end of a LINE everywhere. `strip_lines_matching` is applied line by line, so an anchor there always worked; `replace` and `match_output` are applied to the whole output, so the same anchor only ever matched at the very first byte — and did nothing, silently, on a filter that installs and validates cleanly. Measured: `match_output.pattern = "^ALL SUITES PASSED"` never fired on output whose last line is exactly that, and `replace.from = "^PASS \\((\\d+)ms\\) "` rewrote nothing, while dropping the anchor made both work. One file format, one meaning for an anchor. A hand-written `(?m)` still works, and an unanchored pattern is unaffected.
- A file tokenade does not fold comes back with its own line endings. A compactor that REBUILDS its input re-emits normalised text, and when there is nothing to fold that rebuild is the entire difference: measured on a 29-byte CRLF markdown, the answer was 26 bytes of the same words with every `\r\n` turned into `\n`, and a 15-byte CRLF csv the same way. Three bytes "saved", and `tokenade read x.md > y.md` silently rewrote the file — the harm the trailing-newline rule already names, one layer up. A file big enough to be RESHAPED is a view and still differs however it likes: a CRLF log of 800 lines folds to a template as before. A byte-order mark is removed by the decoder before any compactor sees the text, and that is unchanged.
- A compacted answer is never longer than what it replaced. Every comparison on the way to delivery weighs tokenade's own token ESTIMATE, and the agent is billed on a different tokenizer. Measured on a 6,579-byte YAML of 400 `key: value` lines: the estimate read 2,839 tokens in and 2,373 out — a saving — while the tokenizer that actually bills read 2,399 in and **2,475 out**. The fold dropped 222 lines and the recovery footer cost more than they saved, and nothing could see it because the only number in scope was the wrong one. Bytes are not an estimate, so an answer longer than its input is no longer delivered: the file comes back as it is. An answer of the same length still is — a reshape can cost fewer tokens at equal bytes.
- A browser accessibility snapshot keeps every ref it arrives with, on every route. `[ref=eN]` is the id `browser_click` and `browser_type` take, and the snapshot compactor preserves all of them on purpose. Two things sent them to the wrong pass. Content detection required a `- generic` wrapper node alongside the refs — Playwright's name for an unnamed div, which a page built from semantic elements never has — so a tree of links was not recognised as one; and the generic repetition fold, which replaces distinct values with a template and a count, then claimed it on size. Measured on a 53,084-byte tree of 500 list items: **500 refs in, zero out**, in 402 bytes that looked complete and could not be acted on. The fingerprint is now the refs and the tree they sit in, and the repetition fold is withheld from any answer carrying handles. Receipts (`Setting up libpkg7 (1.0.7-1) ...`) still fold exactly as before.
- `tokenade web` on a page with no readable text says so instead of answering with a newline. Measured on five shapes — an empty body, whitespace only, a comment only, empty tags only, a `<style>` only — the reply was **one byte, exit 0, nothing on stderr**: indistinguishable from a crash, a truncated fetch, and a page that really is blank. The batch route already refused the empty one by name, so the two spellings of one command disagreed about whether this is worth saying. The reply now names the source and says the blank is the whole answer, not a truncation.
- Tokenade's own subprocesses are never compacted, and never counted as savings. `pack` asks `git ls-files` which files exist, `web` asks `curl` for a page, the grep hook runs `rg`, a media read runs `ffprobe` — tokenade reads all of that itself and none of it reaches an agent. Put any interception layer in front of those programs (the PATH shim shipped before 0.9.5, which the installer removes but an install that never upgraded still carries; a wrapper script; a shell function) and both halves went wrong: measured with such a `git` first on PATH, one `tokenade pack` booked **`git-ls-files 8059 → 249`** plus a recovery row — a saving on 2,699 file paths nobody was going to pay for — and **pack's own answer came back different**, because it had parsed the fold instead of the file list. Every subprocess tokenade runs for itself now carries a marker, `wrap` runs it untouched and books nothing, and a check keeps a new one from opting out. An explicit `tokenade wrap` is unchanged: you asked for it, so it folds and it counts.
- Several questions in one `--prompt` now share the answer budget instead of each being given all of it. Measured on this repository's `CHANGELOG.md`, which `tokenade read` delivers whole in 4,699 bytes: one question came back at 7,053 bytes, four at 30,592 and twelve at **82,056** — seventeen times the document, from the flag whose purpose is to cost less than reading it. At sixteen questions it was worse than expensive: the answer overran the delivery bound and came back as an outline carrying **six** `### Q` headings, with the other ten questions gone and nothing saying so. The same sixteen now return sixteen answers in 17,263 bytes, and a batch costs about one budget however many questions it carries.
- A `tokenade read` of a FILE now says how to get back what it folded. Reading a log through `tokenade read -` ends with a recovery pointer; reading the same bytes as a path ended with nothing at all — measured at 44 KB, 454 KB and **4.6 MB, where 4,608,890 bytes came back as 154**, one correct shaped line, naming no next step, while the guidance shipped with tokenade tells the agent to run `expand-ref` with "the hash printed in the compactor's banner". No banner and no hash are emitted on that route, and the right answer is not to write one: a file already holds every byte. The fold now closes with the file itself — `tokenade read <path> --prompt "…"` for what you need from it, or grep it — and still writes nothing to the cache. A read that folds little enough to matter says nothing, as before.
- A repeat is folded to a `§ref:` pointer only when the pointer is smaller than the bytes it replaces. `tokenade read` — and every plugin bridge, which goes through the same path — asked nothing at all before substituting one. Measured: a **188-byte file came back as 154 bytes of pointer**, the content minus 34 bytes plus a whole turn of `expand-ref` to get it back, and an **empty file came back as those same 154 bytes for zero content**, telling the agent to "ask it what you need" about nothing and calling a file it had never seen "identical to a prior call". The floor is now stated against the marker's own measured cost, and content has to be worth at least twice it — the margin the delivery path already checked. A 1,968-byte re-read still folds to 154 bytes; 42 and 252 come back whole.
- `dashboard --days N` is refused where it cannot apply. `--json` and `--html` are the LIFETIME view on purpose — they read the ledger union its durable rollup, and rollup rows carry no date — but both accepted `--days` and answered with the whole history anyway. Measured on a ledger holding rows 60 days old, the text dashboard answered **5 operations at `--days 7` and 8 at `--days 90`** while `--json` returned the same 8 for both. The flag now says why it does not apply and points at the surface that windows.
- Four more file locks stopped waiting forever. The savings ledger was bounded first; the licence reporter, its spill drain, the redaction counter and the recalc marker each held one too — **all four on the startup path of every invocation**, so a slow holder anywhere delayed the command you actually ran. Each already treated a lock failure as "carry on", so the unbounded wait bought nothing. They wait 250 ms and then get out of the way; the ones that rewrite a file skip their pass instead, and the next invocation does it.
- A picture tokenade just decoded is named as a picture. Reading a TGA or a Radiance HDR printed `[tokenade:image 120x80]` — the decoder had opened it and measured it — and then, on the very next line, stashed it as `<hash>.bin` with "Binary content … Inspect with: file, xxd, hexdump": the advice for something opaque, about a file whose dimensions had just been printed. Neither format has a magic number the sniffer knows, and the path — which carries an authoritative extension — was not being passed to the stash. It is now, so the file keeps its own extension and the advice is `identify` / `exiftool`. Netpbm (`.pnm`/`.pbm`/`.pgm`/`.ppm`) was in the same position and is fixed with it; the advice list now asks the decoder which formats it can read instead of repeating them.
- RTF documents no longer come back with every accented character doubled. An RTF writes a Unicode character as `\u233` followed by a FALLBACK for readers that cannot decode it, and LibreOffice writes that fallback as `\'e9`. Tokenade skipped the fallback only when it did not start with a backslash — which is Word's form — so a LibreOffice document read `\u233\'e9lusif` as **"éélusif"** and opened every quotation with "««". The `\ucN` count is now read from the document too, so `\uc0` (Word emitting no fallback at all) no longer loses a real character. And `\~`, a non-breaking space, is a space instead of a literal `~`.
- A busy savings ledger can no longer make your command wait. Every write to it took a cross-process lock with **no ceiling on the wait**, while each of those call sites already ignored a lock failure — so the unbounded wait bought nothing and could cost everything: in this repository's own test suite, with dozens of wrapped commands running at once, one `tokenade wrap` had still not started its work after **30 seconds**, four times over one session, where the same command alone takes a quarter of a second. The wait is now capped at 250 ms. Appends go ahead regardless, exactly as they did on a lock error; rotation, rollup and prune — the passes that rewrite the file — do nothing at all rather than rewrite it under whoever holds the lock, and run on the next write instead.
- `env` gets the same fold as `printenv`. `env` is two commands sharing a name: a launcher (`env FOO=1 cargo build`, whose output is cargo's) and the environment dump. Routed as a launcher with nothing to launch, the dump fell through to the plain generic pass — measured on a real environment, 822 bytes came back as **786 under `env` and 354 under `printenv`**, the same bytes, and the spelling everyone types was the one missing the fold that drops the XDG/GNOME/GTK/Qt session block, truncates `PATH` and redacts credential-named variables. `env FOO=1 <cmd>` still routes as `<cmd>`. This was never a leak: the redaction pass runs on both routes.
- `<tool> --help` comes back whole. A help text is a lookup table, and every fold of one was buying its savings out of the table: `tar --help` went in with **46 short options and came out with 12**, mentions of `--exclude` down from 16 to 5, under a banner reading `282 line(s)` and not "your options are gone". Nor is there a fold that keeps them and still pays — measured over ten help texts, the option lines and their continuations are 26% to 99% of the bytes (median ~85%). `--help`, `--usage`, `-?` and a leading `help` subcommand (`git help`, `go help`) now pass through untouched. `-h` does NOT: it is `--human-readable` on `ls`, `du`, `df`, `free` and `sort`, and those keep folding.
- An archive rollup no longer tells you to pass a flag that does not exist. The directory grouping closed with "pass `--no-fold` to expand"; that spelling appeared exactly once in the entire codebase — in the message advertising it. Nothing parsed it, so following the instruction cost a turn on `sh: -- : invalid option`. The line now names what is actually true: pass a path or glob to the listing. A test sweeps every message that tells you to pass a long flag and fails when the flag is spelled nowhere else.
- A dependency tree is no longer counted as a pile of files. `cargo tree`, `npm ls`, `pnpm why` and `poetry show --tree` draw the same box characters as `tree(1)`, and that was enough to route them into the file-listing rollup whenever no command name was there to route by — which is every MCP tool result and every plugin-bridge result. What came back was not a worse fold but a false one: on this repository's own `cargo tree`, **"1034 file(s) across 2 directories"** and an extension histogram led by `.1` at 13.7%, which is the middle field of the version numbers read as a file extension. The tree now keeps its edges. A `tree(1)` listing is unaffected, including one whose names carry dotted numbers (`libLLVM.so.21.1`, a `3.11` directory).
- `getfacl -R` answers the question it was run for. It prints one seven-line record per file, and the fold dropped two boilerplate lines out of the seven — on a tree that is barely a fold at all: measured on `getfacl -R crates`, 265,874 bytes came back as 123,928, while the same bytes routed through no compactor at all came back as 7,702. The listing is now grouped by the ACL itself: every distinct one shown once, **rarest first**, with how many paths carry it and a few examples. A tree's ACLs are identical almost everywhere and the outliers are the reason to run `-R`, so a single differing file survives a tree of thousands — 448 paths and 4 distinct ACLs fold to 209 tokens with all three unusual files named. A single path has nothing to group and keeps the older fold.
- `lsblk -f` gets the same fold as plain `lsblk`. The header check asked for `SIZE` and `TYPE`, which describes the default column set and nothing else, so the filesystem view — which carries no `SIZE` — was passed through whole. On a machine that runs snaps that is most of the table: measured on a 34-row listing, **25 rows are read-only squashfs loopbacks under /var/lib/snapd**, and they are what the fold exists to drop. Any column set now counts as `lsblk` as long as the header begins with `NAME` and names two of the tool's columns; a table that merely starts with `NAME` still does not.
- `ls -lR` folds like `ls -l -R`. The dispatcher looked for `l` inside a bundled short flag (`-la`, `-lah`) but matched `R` only when it stood alone, so every clustered spelling took the long-listing path and the recursive fold never ran. Measured on `ls -lR crates`, 138,623 bytes: **74,817 delivered as `-lR`, 11,590 as `-l -R`** — the same command, the same bytes, folded 6.5x worse because the letters were written together. `-Rl`, `-aR` and `-Rv` were affected the same way; `ls -r` is still `--reverse` and is not routed as recursive.
- A short `-v` on `ls`, `od`, `hexdump`, `nl` or `join` no longer turns compaction off. Tokenade passes output through untouched when you ask a program to be verbose, and that rule reads a lone `-v` without knowing what the letter means: on these five it is not a verbosity dial at all — `ls -v` is `--sort=version`, `od -v` and `hexdump -v` are exactly the flags that STOP repeated lines being collapsed, and `nl -v` / `join -v` take a value. Measured on `ls -R crates`, 36,416 bytes: 3,356 folded, and 36,416 — nothing at all — when the same command was written `ls -v -R`. `grep -v` and `iptables -v` were already exempt; `tar -v`, `ldd -v` and `mkdir -v` still hand you the raw bytes you asked for.
- `tokenade discover --days N` scans everything when N is larger than your history, instead of answering from an arbitrary window. The window was computed as `N * 86400` seconds, which overflows above roughly 2.1e14 days: the command then reported a different set of tools than its own 30-day default did, with no warning that the number you gave had been turned into something else. Asking for more days than exist now means all of them.
- A fold that ran twice says what the lines it dropped stood for. A compactor that collapses repetition writes `(×47)` on the line that replaced forty-seven; when the collapsed view is itself too long, a second pass elides some of those lines — and the footer, counting lines of the view it could see, called each one `1`. Measured on `lsof -n -P` piped through `tokenade filter`: 370,367 lines in, and the answer closed with `folded 8147 line(s) total`, every one of them a collapsed run. The number an agent judges "how much am I not seeing" by understated the loss by two orders of magnitude. The footer now reads `folded 2821 line(s) total, standing for 28210 line(s) of the original output`, taken from the run markers on the lines it dropped — the view already carried the fact. An ordinary fold, where the two numbers would be the same, says nothing extra.

- `tokenade read-mode` tells the truth about the knob it exists to explain. Two things were missing. A value the ladder does not know was echoed back beside a mode it had not chosen: `TOKENADE_READ_MODE=agressive` — one `g`, the French spelling — answered `active: task (TOKENADE_READ_MODE=agressive)`, which reads as agreement, while every fold stayed at the default. The parse stays forgiving on purpose (no command should fail because a shell exports a misspelled variable), so the status is where it has to be said, and it now names the spellings that exist. `read-mode --json` carries the same fact as `env_recognised`. And the ladder was printed with nothing about how far it reaches: measured on a 188 KB kernel log, all four rungs returned byte-identical output through `read` and through `filter`, while `git ls-files` moved 2,512 → 488 → 343 bytes across reference, task and aggressive. The ladder is wired into some compactors, not all of them, and the status says so in a form you can check rather than take on faith: a fold that honoured the mode stamps it in its own banner, `[tokenade:git-ls-files·aggressive]`.

- `--json` and `-o <mode>` no longer both claim the shape of an answer. `tokenade map <path> --json -o paths` returned the full JSON document, byte-identical to `--json` alone: measured on this repository, 5,728 bytes where `-o paths` alone returns 1,159 — five times what the caller asked for, silently, from a tool whose subject is tokens. Same on `query` and `impact`. The combination is now refused, naming both flags and saying that the JSON already carries the fields the mode would have selected. Either flag alone is untouched. `skeleton` and `semantic` have no `--json` of their own and keep the refusal they already gave — `unknown flag '--json'`, which says more — and a check drives the binary to keep the two groups from drifting apart.

- `tokenade read <file>` gives back exactly the bytes it did not fold. It ended every answer with a newline of its own: a 25-byte file with no trailing newline came back as 26 bytes, and a file that already ended in one came back with a blank line after it. Invisible in a terminal, and a corrupted artifact the moment you write it down — `tokenade read x > y` produced a file whose checksum no longer matched x. The rule that answers this was already written and already shared: a VIEW needs closing, because a summary would otherwise run into whatever prints next, and bytes handed back unchanged need nothing. `wrap` and `filter` ask it; `read`, the content entry point, was answering with an unconditional `println!`, and so was `tokenade snapshot`. Both ask it now. A file large enough to be folded still ends with a newline, because that answer is a view.

- A search that finds nothing says what it searched and what to try. `tokenade query <name>` answered `no symbol matching '<name>'` and stopped there when nothing was even close — a confident negative that reads the same whether the name is absent, the index is stale, or you are simply standing outside the project, which is a real way to get this answer. It now names the corpus it looked through (`25278 symbols in 1680 indexed file(s) searched`) and points at `tokenade semantic "<name>"`, which searches by meaning rather than by name — the verb a caller who only has a guess at the name actually wants. `tokenade semantic` had the same bare shape, `no match for '<query>'`, and now names its corpus too, pointing at `grep -rn` for a literal string and `tokenade query` for a symbol. It deliberately does NOT suggest raising `--limit`: a query that matched nothing was cut by relevance, not by depth. The line these three commands share had drifted into three different spellings, and a build-time check now fails if a fourth appears outside the one place that owns it.

- `tokenade semantic` says when it stopped at the depth it was given. The ranking returns the top `--limit` hits, ten by default, and the listing said nothing about the rest: ten rows came back looking like all there was. The same command in another mode already knew better — `-o count` marks a pool-filling count with a `+` because "a count that fills the pool is a FLOOR, not a total" — and the help promises exactly this for the neighbouring flag, that a truncated answer never looks complete. Measured on this repository, `semantic "dedup" -o count` answered `40+` while the full, paths and outline modes each returned ten rows with no horizon in sight. All three now close with `[tokenade:depth] 10 shown — the ranking considered 40+. Raise with --limit 20 to look past the first screen.` It appears only when the depth was actually reached: an answer that came back short was cut by relevance, not by the depth, and pointing at `--limit` there would send you down a path that changes nothing.

- `tokenade semantic --limit` refuses a value that is not a depth. `--limit abc` and `--limit 0` were accepted and dropped: the answer came back as the default ten hits, byte-identical to passing no flag at all, with exit 0 — so a caller who asked to look past the first screen got the first screen and no way to know. Every sibling already refuses (`--budget expects a token count`, `--max needs a positive integer`, `--context value 'abc' is not a non-negative integer`), and this verb's own help states the rule: an unknown flag is refused rather than folded into the query, so a typo fails loudly instead of quietly changing what you asked. A value that is read and dropped changes what you asked just as quietly. Both spellings are checked, `--limit 3` and `--limit=3`, and `-n` with them. `--budget 0` is untouched: zero is that flag's way of saying no ceiling.

- `tokenade map <path>` accepts a path spelled from the workspace root, from anywhere in the tree. The index a command is handed is re-based to the directory you are standing in, so from `crates/tokenade-cli` a sibling's file is stored as `../tokenade-core/src/…` and `tokenade map crates/tokenade-core/src` answered `no indexed file under 'crates/tokenade-core/src'` — while the same message said, in the same breath, that paths are matched from the workspace root. Both spellings now resolve, and the one you can see around you wins when both match: re-basing rescues a path that would be refused, it never re-reads one that already works. A path that exists nowhere is still refused, and the message now says which directory it matched from. `tokenade impact` has taken both spellings for a while; this is the same rule, one command over.

- A mistyped path is no longer searched for on the web. `tokenade search` reads a readable file as a saved results page and treats anything else as a query, so a path that was not there became the query itself: `tokenade search /nope/missing.html` returned `[tokenade:search via bing+duckduckgo] "/nope/missing.html"` and exited 0. Two things went wrong at once. A typo reads as a successful read of the file, because the exit code says it worked. And a local path — which carries a user name, a client name, a project name — is handed to two search engines. An argument that opens like a path (`/`, `./`, `../`, `~/`) or ends like a saved page (`.html`, `.htm`, `.xhtml`, `.mhtml`), with no whitespace in it, is now refused when no file is there, naming the file and saying that nothing was sent. A query may still carry a slash — `BurntSushi/ripgrep` searches as before, and so does a sentence like `difference between index.html and index.htm` — and `--html` still forces the page reading, error and all. Every positional is checked, so a batch of queries cannot leak what a single one refuses.

- An empty search answer names the wall it actually hit. `tokenade search` says why it came back with nothing, so that an agent told the engines refused can fall back to its own search instead of concluding the web is empty on the subject — but the reason was `no engine was reachable` for every empty answer, including two where no engine was involved at all. `tokenade search <file|->` compacts a results page you already have and queries nobody: a saved page it could not parse came back `no usable results for "saved page" — no engine was reachable`, sending you to check your network for a page sitting on your disk. And an engine that answers with zero hits was reported as unreachable too, while its own name was in the same outcome. Each case now says what happened: the engines that refused and why, or that the engines answered with nothing, or that no engine was queried.

- A test run in which nothing failed no longer comes back reporting failures. Folding a long run keeps the lines that look like problems and elides the rest, and it decided that by scanning each line for words like `failed`, `panic`, `error`, `timeout`. Test names are written in English and name exactly what they defend — `a_pipeline_that_hid_a_failure_says_so`, `read_prompt_without_a_value_is_a_clean_error` — so the scan read the NAME and not the outcome. Measured on a real 8,884-test `cargo nextest run` with zero failures: the fold announced `10 kept below because they look like failures` and listed ten PASSING tests. On a 400-test run with exactly one failure, the banner read `98 problem(s) first`. And a fully green summary line — `400 tests run: 400 passed, 0 failed, 0 skipped` — was itself promoted as a problem, for the word `failed` standing next to a zero. Where a runner prints its own verdict, the verdict now decides: cargo-nextest, libtest, `go test`, pytest and jest verdicts are all read as verdicts, and a count of zero is not a problem. The other half was worse and is fixed with it: `FAIL [   0.004s] (4/5) …`, cargo-nextest's way of saying a test failed, matched no keyword at all — `fail` alone is too broad to be one — so the one line that mattered could be elided from the middle of a long run while ten passing tests were rescued in its place. Failures are still hoisted to the top, and now only failures are.

- `tokenade file-search` is gone. It looked for a passage inside ONE file by meaning, and `tokenade read` now does that better on every axis: `read <file> --prompt "<question>"` answers the same question over the same file, and it reads PDFs, .docx, spreadsheets and slides, where file-search could only take UTF-8 text and failed on the rest with a decoding error. Asked the same question of the same file, `read --prompt` answered in 1,326 tokens against 5,195, and it now labels each passage with the file's own `[lines A-B]` so `read --lines A-B` can go straight back to the region. For a literal string `grep` is still the cheapest thing on the machine, and `tokenade semantic` still searches by meaning ACROSS a repository. What the verb had that nothing else did was per-file semantic lookup, and it never worked: its nearest-neighbour search ran over every file ever indexed on the machine instead of the file you named, from its first commit to the fix a few days ago, so a file's own recall fell as other files were indexed around it. Nothing indexed from your files is stranded: the chunk store it built is no longer written to, `tokenade evict-stale` still clears it on the same seven-day TTL, and `scrub-secret` and `redact` still reach into it, so a secret that went in before can still be taken out.

- `tokenade read --prompt` says WHERE each passage came from. A retrieval that answers without saying where leaves the next read with nothing to aim at: you know what the file says and not what to open. Each passage now carries `[lines A-B]`, and the numbers are the file's own — matched against the bytes on disk, not against the compacted view the retrieval worked on. A passage the file cannot confirm gets no label at all, because a wrong line number sends the next read to the wrong place and looks authoritative doing it: a block is anchored on the first line that can be located (a `## 1.1.4` heading is too short to be evidence), a truncated line is matched by its first 40 characters, and a passage assembled from several distant regions of the file — the tail of an answer, where the recall pass unions in what the main retrieval missed — carries no line numbers at all, because it has no single span and naming its first line would make `[lines A-B]` mean one line in twenty on that block and the whole passage everywhere else. On a slice the labels are still the file's lines, not the slice's. The next move is `tokenade read <file> --lines A-B`, and the answer says so once per context — not on every call, and again after a compaction, which is where an agent's memory of it goes.

- `tokenade read --lines A-B` reads one region of a file instead of the whole of it. A file too big to take at once was all-or-nothing: an agent that already knew WHERE the answer was — from a search, a stack trace, an earlier read — still had to pull the entire document to see forty lines. The range is 1-based and inclusive at both ends; `A-` runs to the end, `-B` from the start, and a bare `A` is one line. The answer opens with `[tokenade: lines A-B of N]`, so paging through a large file needs no guess about where the last piece stopped, and the region is what the compactor is given — not the whole file with a note. A range that starts past the end is refused and says how long the file is, rather than quietly handing back the last line; a range written backwards is refused rather than silently swapped. It composes with `--prompt`: the question is then asked of that region only.

- `tokenade redact` removes a private key, not just the line it starts on. The command rewrites a file so it can be shared, and it streams line by line because the file may be gigabytes — but a private key is not one value on one line: it is a BEGIN marker, a body, and an END marker. The rule that erases the whole block cannot fire on a reader that hands over one line at a time, so the BEGIN line became `<redacted-private-key>` and the key body and the END line were written straight through into the `.redacted` file the command reports as done. The same bytes on the path that feeds a model came back with the whole block gone, so the two disagreed on the one thing this verb exists for. The streaming path now carries the little state that rule needs: the block is replaced by its marker, the lines around it are untouched, and a second pass over an already-redacted file still changes nothing. Rotate any key that went through the old path — the `.redacted` file it produced may still contain it.

- `tokenade shell-init` refuses an argument it does not understand. It accepted anything and printed the default fragment: `--json`, `--nope`, `-x` and a bare `garbage` each returned success and the same 4,916 bytes, while `detect`, `read-mode`, `measure`, `receipt`, `semantic-status`, `incompatibilities`, `mcp-stats` and `hooks` all refuse an unknown flag. The silence costs something here, because the argument that was ignored decides which shell the fragment is written for: `tokenade shell-init fish | source` — the flag forgotten, the shell named as a positional — printed POSIX syntax into fish and said nothing, and `-all` with one dash printed the short command list where `--all` prints six times as much. Unknown arguments are now named and refused, with the nearest real flag suggested, and a shell named without its flag is answered with `--shell <name>`. `--shell` with no value after it is refused too, rather than swallowing the next flag as the shell name.

- `tokenade pack --budget N` counts the bundle it actually writes, not just the file contents inside it. Every included file is rendered as a `## path` heading, a fenced block and the blank lines around them — about a dozen tokens of scaffolding — and none of that was charged to the budget. A file with no content therefore cost nothing and always fitted, however small the cap. Measured on a fixture of 60 empty files and one small one, `pack --budget 50` included all 61 and returned 714 tokens: fourteen times the budget, nearly all of it headings wrapped around empty fences. The same run now includes three files and returns 284 tokens. Files with real content were never affected much, since their text dwarfs the wrapper; what changes is that a budget too small to pay for a section no longer buys it. One function now spells a file's section for both the planner and the renderer, so the price and the page cannot drift apart again. The help was wrong in the same place and says it properly now: the cap covers the file sections, headings and fences included, while the summary header and the ten-name floor of the omitted list sit outside it.

- The command you run to recover folded bytes gets the bytes, not another pointer. Every fold prints a hash and says to run `tokenade expand-ref <hash>` for what is behind it, and the shipped guidance calls that "the recovery path you actually want 99% of the time". Run through the wrapper, its answer was compacted and deduped like any other output, so it came back as `§ref:<hash>§ (…, identical to a prior call — ask it what you need: `tokenade expand-ref <hash> --prompt "q1, q2"`)` — the command that had just run, naming the hash it had just been handed. An agent asking to recover is saying it does not have the content, so that answer is a closed loop, and the only way out was redirecting to a file. Typed plainly the command was never affected: the Bash hook leaves a command alone when its program is tokenade. Any launcher in front of it defeats that test — `timeout 60 tokenade expand-ref …`, `env FOO=1 tokenade …` and `nice tokenade …` were all rewritten into a wrap, measured on all three. A recovery command's output is now served exactly as it was printed, whichever way it is spelled and whichever channel it arrives through, and an ordinary repeated command still folds as before.

- `tokenade search --answer` reads the results it quotes through the same dedicated readers as everything else. `--answer` fetches the top three results and returns the passages instead of the links, and the top results of a web search are exactly the pages a reader exists for: a GitHub issue, a reddit thread, a YouTube page. The check that was supposed to prevent this asked whether the FILE containing a fetch mentioned a reader; the answer path sits in the same file as one that had just been fixed, so it stayed green over a function that consulted nothing. It now asks per function.

- Fetching several URLs in one call no longer loses the dedicated readers. Seventeen sites have one — an issue comes from the GitHub API, a thread from old.reddit, a crate from the registry — and `tokenade web <url>` has used them since the day a plain fetch of a reddit thread returned 37 characters of JavaScript shell. - Fetching several URLs in one call now says which of them failed. `tokenade web <a> <b> <c>` labels each target with its URL, but the section for a page that did not load carried only whatever the server sent back — a 404 whose body reads "Not Found" was indistinguishable from a page that says so. The single-URL path was given the HTTP status and the landing URL a while ago, with the measurement behind it: 23% of real fetches are non-2xx and 11.6% end on a different host. The batch — the call tokenade's own guidance tells agents to prefer — never got them. Every target now opens with the same line the single path prints, `[tokenade: HTTP 404 — the page does not exist. What follows is the ERROR page, not the requested content.]`, including the redirect note when the fetch landed somewhere else; a page that loaded normally gains nothing. - `tokenade hooks tail` returns the number of records its help promises, and `--json` now answers with a document. - `tokenade scrub-secret` shows what it will change and asks before changing it. A real run therefore lists every file and count first, then asks. `--yes` answers up front, and is required when stdin is not a terminal: there is nobody to ask, and an agent must not rewrite your stores on its own. `--dry-run` still previews without touching anything, and a run that finds no occurrences never asks, because it would change nothing. - `tokenade scrub-secret` no longer leaves a copy of the secret it just removed. The disclosure stash, where a big command output is parked so `expand-ref` can hand it back, lives under your cache directory instead, so every stashed blob read as one of your files. An agent reading the old sentence avoids a spelling that works and, worse, believes output it is about to receive is raw. The two texts now say what the third says, and a check fails the build if a shipped text mentions an absolute path without saying it is intercepted, or goes silent about it. The block in your `~/.claude/CLAUDE.md` is refreshed in place on the next install or upgrade.

- `tokenade wrap --split-streams` and `tokenade filter` no longer alter the bytes they hand back. `--split-streams` exists so that `cmd > data.json` behaves as it does without the wrapper, and it was dropping the final newline of any stream the compactor reshaped — `echo hi` came back as `hi`, on 7 of 14 real commands, on stdout and stderr alike. `tokenade filter`, which agents are told to pipe noisy output through, had the opposite defect on the branch that returns the input verbatim: `printf 'no-newline' | tokenade filter cat` returned 11 bytes for 10. Neither is visible in a terminal and both corrupt a redirected file. One rule now answers the question for every place that prints — is this a view, which needs closing, or the caller's own bytes, which need nothing — and it was spelled out separately in seven places, which is how the two ends of `wrap` came to be wrong in opposite directions at the same moment. A build-time check fails if an eighth place spells it out again.

- `tokenade wrap 'cmd' > file` writes exactly what `cmd > file` writes. Output the compactor passed through unchanged was coming back with a newline the command never printed. The wrapper terminates output that does not end in one, which is right for a compacted VIEW — a summary that would otherwise run into whatever prints next — and wrong for bytes it decided to hand back untouched: `printf 'no-newline'` returned 11 bytes where the command produced 10. One byte is a corrupted artifact for anything that redirects — a checksum that no longer matches, a fixture that no longer compares equal — and it is invisible in a terminal, which is where this survived. The terminator now fires only when the pipeline actually reshaped the output, which is where it earns its keep: with it removed entirely, 30 of 36 real commands lost their final newline, because folding a view strips it. A test that pinned the old behaviour used `printf x` as its witness, the one shape where nothing folds; it now uses one where something does.

- Your project indexes no longer fill up with directories that never existed. - `tokenade audit-claude-md` says how much duplication its own listing is hiding. - `tokenade gain` tells you what the server will actually meter. The savings figure credits each event once, and the local rule for "same event" is finer than the one the licence server's ingest uses: it also looks at which command ran and in which session, so three variants of one command in the same second count as three here and as one there. That is deliberate — they really are three commands — but it means this figure can sit above what your account shows, and nothing said so. Three comments in the code asserted the two counts were identical; they were, until the local rule changed, and then they stood wrong. `gain` now prints the metered figure and its event count beside the total, and only when the two actually differ, so a caveat that is always on screen does not become invisible. `--json` carries `operations_as_metered` and `saved_as_metered` unconditionally. On the install this was measured on the gap is 62 events and 1,473,059 tokens, 0.24%.

- Commands you run in parallel are each counted. Every savings figure credits a ledger event once, so that an append landing twice — a retried hook, a replayed rollup — is not paid for twice. The identity used for that was the timestamp, the operation, and the two token counts, and two comments in the code argued that two different events sharing all four are "indistinguishable from a loop" — while the row carries the command label that distinguishes them. They collide precisely because they are variants of one command: `kubectl get pods`, `kubectl get po -A` and `kubectl get pods --all-namespaces` fold the same data to the same two numbers in the same second, so three real commands were credited as one. Measured on a real ledger, 22 such collisions swallowed 47 events and 1,279,063 tokens; running 24 distinct commands at once, every surface reported ONE operation and the signed receipt certified it. The label and the session are now part of the identity, so parallel work is counted as parallel work, and a doubled append still collapses — it repeats every field. The same identity is now computed in one place for all three surfaces, two of which had already drifted on how they read a legacy row.

- `tokenade gain` and `tokenade dashboard` say how much of the total is an approximation. Part of the savings figure credits a delivery cap rather than exact arithmetic: on a channel where the agent would have REFUSED an oversized payload instead of truncating it, crediting the cap is a deliberate stand-in. That slice stays in the total on purpose, and the decision is only honest if it is stated — which only the signed receipt did. `gain` printed the total in silence while disclosing two smaller estimate categories in the very next lines: 827,982 and 127,321 named, against 4,736,778 unnamed on this install. Both surfaces now carry it, in the text output and in `--json`, and the three of them are checked against each other on one ledger so they cannot drift apart again. No number moves: labelling is not subtracting.

- A re-read of a file you changed serves a diff on the same terms whichever way you read it. When a Read comes back to a file tokenade already holds, it answers with a diff instead of the whole file, but only when the diff is much smaller — a diff that is barely smaller is worse than the file, because you get the same lines back as context plus markers and still have to apply the change in your head. Three read paths each decided that for themselves, and one of them served a diff at 20 % saved where the other two required 40 %, with nothing saying why and no test on the odd one out. That is not a band nobody reaches: measured over 200-, 500- and 2000-line windows, a diff lands between 20 % and 39 % when 11 to 14 % of the lines have changed, so the same edit was answered with a marginal diff after a paginated read and with the clean file after an exact one. All three now ask the same question, the floor is stated in one place with the measurement behind it, and a build-time check fails if a fourth path picks a number of its own.

- Your debug log no longer keeps credentials in the clear. `TOKENADE_DEBUG_LOG` writes a record per event, and it scrubbed secrets out of five field names — `command`, `script`, `error`, `stderr`, `url` — and only at the top level of each record. The log holds 216 different kinds of event carrying 241 distinct field names, so that list covered a fifth of them and nothing added since. Measured on a real log: a bash command line landed in the clear under the name `label`, an authentication failure under `reason`, and a `command` nested one level inside another field was skipped despite having the right name. This log is off by default, but it is not private: `tokenade report` collects it into a support bundle by name, so what lands in it is what you hand to someone else. Every string in a record is now scrubbed, at every depth, with the argument-aware pass — the one that catches `-p <password>`, where the secret is a separate word from the flag — still applied to command lines and only to those, so an error message keeps its wording. Numbers, field names and ordinary paths are untouched.

- Two tokenade runs finishing together can no longer scramble a row of the savings ledger. The ledger is appended to by every wrapped command, its lock is process-local, and the argument for safety across processes was that the operating system appends small writes whole — which it guarantees only below 4 KB. That was written down as "every record we emit is under 200 bytes" and had never been measured: on a real ledger, 791 of 875 rows were over 200 bytes and seven were over the 4 KB limit, the largest 8,696 — a `sha256sum` over several hundred files, whose command line alone came to 8,359 bytes in the row's label. A row that long is split by the kernel, and a second command writing at that moment lands inside it. The label is now trimmed to a length that keeps the row well under the limit, marked so a reader never mistakes a shortened command for the whole one, and trimmed after scrubbing rather than before — cutting first can split a secret in half, and half an access key no longer matches the pattern that would have masked it. The debug log gets the same bound on the whole record; measured at 727 bytes at its largest today, so nothing in practice is shortened, and the guarantee now holds rather than happening to.

- Two tokenade runs at the same moment can no longer corrupt the savings ledger. Rotating or pruning `gain.jsonl` rewrites it through a temporary file and renames that over the original — the standard safe pattern, except that the temporary file was named the same in every process (`gain.jsonl.rotating`). The ledger's write lock is process-local, and its own comment says cross-process safety rests on the operating system making small appends atomic, which says nothing about the whole-file rewrite rotation performs. Two commands crossing the rotation threshold together — which is exactly when rotation happens, on a busy machine — wrote into that one file and renamed a half-written copy over the accounting every figure is derived from. Seven places had each spelled this out for themselves, all with a name every process shares: the ledger's rotate, prune, rollup-merge and recalculate paths, the statusline cache, the bypass counter, and the transcript cache. They now call one writer that names its temporary file after the process and a counter, carries the destination's permissions over so a file you tightened is not widened by a save, and removes the temporary file if the rename fails. A build-time check fails if an eighth place spells it out again.

- `tokenade dashboard` reads your agent transcripts once instead of five times a run. It was the only surface that walked `~/.claude/projects`, and it did so five times over — one pass per figure it reports — materialising every line of every session file as JSON and discarding almost all of it. On a 1.8 GB history that took **27 seconds**, while `gain`, `receipt` and `statusline`, reading the same ledgers, answered in 7 to 11 milliseconds; and it grew worse every day, because the history only ever gets longer. Each session file is now reduced once to the handful of fields those figures need, kept in a small compressed cache beside the ledger, and re-read only from the byte where the last read stopped — a file that has not changed is not opened at all. The same command now takes **2 seconds**, the first run after an upgrade takes about seven, and the cache is 9.8 MB for that 1.8 GB of history. Every number it prints is unchanged, which is checked against the previous implementation on a fixture covering each of its branches.

- `tokenade pack --budget N --json` obeys the budget the same way the text output does. The same rule now serves both surfaces. Nothing is lost by bounding the list: `omitted_count` and `omitted_tokens` still cover every file, and a new `omitted_listed` says how many of them the array holds, so the remainder is a subtraction away.

- `tokenade turn-summary --max N` says when it returned more than N. That floor is worth keeping, and it was silent: `--max 1` on a turn made of rules returned ten sentences, and so did the DEFAULT of five, with nothing in the output or the help marking it — a cap quietly exceeded is one the reader trusts wrongly the next time. - The advice to batch questions says why batching is cheaper. - An image's saving is counted the way an image is billed. - A folded run says what its shape means. When several lines are the same sentence with one value changed, tokenade prints the sentence once as `… (×N)` and lists the values under it, so nothing is lost — but nothing in the output said that. Measured on a 68,000-token document answered through `tokenade read --prompt`: 121 lines of answer, not one of them explaining what `{}` stands for or what the indented values under it are, so `(paragraph {})` reads as literal text. - `tokenade pack --budget N` respects the budget it prints. Files that do not fit are listed rather than dropped in silence, and that list was itself unbounded: on one crate, `--budget 200` returned **16,923 tokens** — one included file of about 199, and 1,233 lines of manifest. An agent that asks for two hundred tokens and receives seventeen thousand of file names has been handed the opposite of what it asked for. - A package version is no longer redacted as a bank account number. The rule that masks 8-to-17-digit account numbers fires when an account word sits within 48 characters, and both halves misfired at once on a real `pacman -Q`: the pattern treats a dot as a word boundary, so it matched the `20260526` inside the version `20260526.0-2`, and the context word came from the package name on the next line, `accounts-qml-module`. One version in 1,533 came back masked, from a listing whose whole purpose is its versions; a `git status` on this repository lost a number the same way. The digits must now stand alone rather than being a segment of a longer dotted or hyphenated token — a real account number does, including when it ends a sentence — and a genuine `Account: 12345678` is masked exactly as before.

- A JavaScript stack trace keeps what follows its frames. Everything printed after the last frame was discarded — silently, with no count and no recovery pointer — and for Node that is the error object: `code: 'MODULE_NOT_FOUND'`, the require stack, the runtime version, which is the half of the trace an agent greps. Measured on `node -e 'require("nosuch")'`: 262 tokens became 191 and all of that left. The Python branch has kept a tail since it was written; the JavaScript one now does too, and it keeps indented lines because Node nests its error object two spaces under the throwing frame.

- A warning printed in front of a JSON document no longer costs the document. Every agent's shell tool merges the two output streams into one — `tokenade wrap` does it deliberately — so a JSON answer arrives behind whatever the tool warned about first, and the detector reads only the head of the output. Measured: `cargo metadata --no-deps` folds from 8,741 tokens to 1,908 on its own and returned all 8,757 of them the moment cargo's one-line `warning: please specify --format-version` was in front of it, a fourfold loss on the shape agents ask for most. Three of five real-world prefixes lost the document whole. A short run of leading diagnostic lines is now stepped over, kept verbatim — hiding a warning to compact the thing it warns about would be a bad trade — and the document behind it is folded. YAML and CSV were never affected; their detectors read lines rather than the head.

- A certificate printed as text survives compaction. `openssl x509 -text` was folded by dropping every line indented by four spaces, on the grounds that a hex dump looks like that — and so does the rest of the document, because everything in a certificate is nested under `Certificate:`. Measured on a real bundle: 2,907 tokens became 15, and the issuer, the validity dates, the subject, the alternative names and the key usage were all gone, leaving a heading and a count. The rule now recognises an actual byte dump — colon-separated pairs of hex digits — and only where several such lines run together, so a serial number or a key identifier, which is the same thing typographically but arrives alone, is kept. The same command now saves 82% and answers the questions a certificate is opened for. IPv6 addresses, which are also hexadecimal and colon-separated, are not touched.

- A noise filter that leaves the output enormous now stands aside for the fold that would actually compact it. Some commands are handled by stripping named noise lines and returning the rest, and that result was accepted however big it still was — which blocked the generic fold behind it. On `readelf -a` of a 3 MB binary the strip removed two section-header prefixes, 161,038 tokens became 132,053, and the fold on the same bytes returns **5,483**: the same command now saves 96.6% where it saved 18%. The existing safety net could not see this, because it asks whether a compaction beats doing nothing, never whether it beats the fallback. Across a thirty-command sweep of real output this was the only route affected, and a strip that genuinely removes most of its input still keeps its result.

- A file name is no longer read as a failure. Tables that sort problems to the top decide on words found anywhere in the row, which is right for a status column and wrong for a column of paths: `tar -tzvf` on a real crate archive announced `10 problem(s) first` and promoted `quickjs/test262_errors.txt` above the archive's own tree order, which is the one thing a listing is read for. Words are now looked for outside path-shaped cells only, on both separators, so a `kubectl get pods` row still floats its CrashLoopBackOff to the top and an `ERROR /var/log/app.log` keeps its verdict, since that one sits outside the path.

- A compacted Read that offers you the full bytes names a command that returns them. Ten of those banners said `tokenade expand-ref <hash>`, and above five thousand tokens that command deliberately refuses to dump and prints the recovery menu instead — so the offer cost a turn and answered with a pointer to a second command. A Read is compacted precisely because the file is large: on one install, 218 of 274 read compactions carry a blob past that threshold, four times in five. Where the sentence promises the whole file the banner now says `--raw`, which forces the dump; where it promises one comment or one function body it says `--grep <pattern>`, which is both cheaper and what the agent actually asked for.

- `tokenade style <preset>` names the file it actually wrote. It reported `style set to chat → <your repo>/.tokenade/style.json` while the setting is kept in `$HOME` — so the command announced success and pointed at a file, and a directory, that were never created. Anyone checking whether it had taken effect found nothing there. The message now prints the path the setting was written to, and says the preset applies to every project on this machine rather than implying it is per-repository.

- Refusing to re-serve a document now has to be cheaper than serving it again. When an agent opens the same PDF, spreadsheet or slide deck twice in a session, tokenade refuses the second read and points at the copy already in context. The size gate in front of that decision measures the FILE, which for a document is the wrong quantity — a container is large on disk and small once extracted. Measured on a 33,467-byte deck holding 62 tokens of text: the refusal message costs 102 tokens, so saying "you already have it" made the context 40 tokens **bigger** than simply serving the deck again. The refusal is now weighed against what it would have served, the same way the compactor's own safety net never returns more than doing nothing would. Documents where the refusal genuinely saves — a real PDF, a real .docx — are unaffected.

- `tokenade filter --help` says which fold it does not run. It described its only difference from `tokenade wrap` as who runs the command, so the two numbers read as interchangeable. They are not: `wrap` additionally folds output that no per-command rule shrank into a recoverable stash, and `filter` does not. On `cat /proc/interrupts` — eighty-one rows of three hundred bytes each, a table no compactor claims — `filter` returns the input whole and `wrap` saves 83%. On everything a compactor does claim the two agree within about a point. The help now says so, and says that what `filter` reports is the per-command compactor alone.

- The signed savings receipt now reports the same figure as `tokenade gain`. Both read one ledger over one lifetime scope, and they answered differently: on a real install `gain` said 669,007,667 tokens before and 72,064 operations, while `receipt` — the signed, exportable number a user quotes to say what tokenade did — certified 673,874,356 and 72,179. `gain` credits each distinct event once; the aggregator the receipt, the dashboard and the statusline share did not, so a ledger append that landed twice was paid for twice. The receipt was the high one, which is the direction that matters. There is now one loop with one set of rules, and every surface reports the conservative number. The guard that exists to keep the five surfaces aligned had a fixture with no repeated event in it, so it could not tell the two behaviours apart; it now carries one, plus a pair for every field of the key so that a repeat is collapsed while two genuinely different operations of the same size in the same second are not.

- `tokenade gain`'s per-operation breakdown counts calls, not ledger rows. The ledger is rotated into rollup rows that each stand for many original calls, and the running total already accounts for that — its own comment says counting a rollup as one "would make rotated history look quieter than it was". Eleven lines below, the `N×` column was doing exactly that. On one install the same screen read `operations: 72064` above a column that summed to **1041**, and a row saying `auto:makefile 11×` was announcing eleven calls for a saving accumulated over hundreds. The saved figures were never affected — only the call counts, in both the per-operation and the per-source tables, and in the same fields of `--json`.

- The bypass nudge reaches the agent it is addressed to. When an agent bypasses compaction more than ten times in a day, tokenade says so — and that message was written to the hook's standard error, which a PostToolUse hook does not surface. Measured on one install: **885 recorded fires, not one ever seen**, while every nudge that travels in the hook's `additionalContext` field arrives every time. It now travels the same way, and it is booked as injected context like the others. Once per session rather than on every bypass: the old "loud on purpose" was written for a channel that costs nothing, and the window this was found in held 164 bypasses. The standard-error line stays, for the agents that do surface it and for `tokenade raw` in a terminal.

- A `cookie` module in a symbol path no longer takes the rest of its line. The rule that redacts a `Cookie:` header eats everything after itself to end of line, and it accepted any non-word character before the name — including the `:` of a `::` path separator. So `reqwest::cookie::CookieStore` in a Rust symbol listing came back with everything from `cookie` onwards replaced, and so did any C++ or Rust module of that name. Measured over one machine's real tool output: 13 of the 38 places the rule can fire are that shape, a third of its hits. A real header never has a colon immediately before its name, so that spelling is now excluded and every header form still loses its value.

- A cookie carried as a JSON field is redacted too. `{"headers":{"cookie":"session=…"}}` came back with the value intact — the header rule cannot cover it, since eating to end of line would take every field after the cookie with it. A second rule bounded by the closing quote now masks the value alone and leaves the document parseable.

- `dpkg -l` keeps the legend that explains how to read it. The line `| Status=Not/Inst/Conf-files/Unpacked/halF-conf/Half-inst/trig-aWait/Trig-pend` was replaced by a redaction marker: the value is 68 characters, mixes three character classes and follows a bare `=`, so the high-entropy sweep took it for an assigned credential. The veto that spares an identifier path refused it over a single character, the hyphen in `Conf-files` — ordinary inside a path segment. A hyphen is now allowed there; the requirement that the value contain no digit at all is what keeps that safe, and over one machine's real output the change spares 25 values out of 3,099 candidates.

- `awk -v` and `sort -v` are compacted again. Tokenade stands aside when a command asks for verbose output, and it reads a bare `-v` as that request. On `awk` the letter assigns a variable (`awk -v n=2 …`) and on `sort` it selects version ordering; neither program has a verbosity dial at all, so reading the letter as one only ever cost the fold. Measured: output that folds from 300 lines to 226 without the flag came back whole with it. Same fix as `grep -v`, two more programs.

- A status fold no longer reads column alignment as nesting, and no longer counts one problem twice. Tables that sort failures to the top group each row with the indented lines that continue it, so a promoted failure arrives with the reason it failed. That only makes sense where indentation means nesting. Where it is column alignment the grouping swallows a whole section into one record and hands every line of it that record's verdict: measured on `objdump -d /usr/bin/ls`, 25,855 of 26,196 rows are indented, they collapse into 341 records, and the banner announced `14865 problem(s) first` — 57% of a disassembly — where 155 rows contain a word from the problem list at all. `nm -D` indents 89% of its rows and claimed 108 problems for ten. Worse than the wrong number, the swallowing record is emitted whole, so the fold walked straight past its own line cap and the output opened 200 lines into the file. The grouping now applies only when indented rows are a minority, which is what the `go test` shape it was written for looks like (one row in 302), and a verbose run with two lines of detail under every failure still keeps them attached. Separately the banner counts problems rather than the lines that describe them: an `npm ls` of 126 dependencies reported `126 problem(s)`.

- A recursive listing of a partitioned object store is no longer redacted away. Tokenade's secret redaction spares a value that is a file path, and it decided that by requiring every character to be path-shaped — with `=` excluded, since a trailing `=` is base64 padding. But `data/year=2026/month=08/day=15/part-00042-…` is the layout Spark, Glue and Athena write by default, so every key in such a bucket carries an `=`: an `aws s3 ls --recursive` came back as `data/year=<redacted>.snappy.parquet` on 1,500 lines out of 1,500. A listing is nothing but its keys. `=` is now allowed inside a segment, alphanumeric on both sides, which is what `key=value` looks like and what base64 padding never does.

- `tokenade disclose read <hash>` returns the stashed bytes. It was printing the stash file's extension.

- `grep -v` is a pattern flag, not a request for verbose output. Tokenade steps aside when a command asks for verbosity, since folding output someone deliberately asked to see is the wrong answer — and it recognised `-v` written on its own. On `grep`, `rg`, `ack` and the `iptables` family that spelling means something else entirely, so `grep -rn foo . -v` was passed through raw. Measured over one machine's real command history: 3,701 such calls, 839 of them large enough for tokenade to have folded, around 470,900 tokens.

- A package manager's subcommand reaches its own compactor. `brew outdated`, `gem list` and their kind are compacted by per-subcommand modules, and the lookup only ever tried the bare program name, so the module never ran: `brew outdated` folded 0% where the same output folded 48% once it reached the right one.

- The elision marker in a code skeleton is a comment in the file's own language. `tokenade skeleton` replaces a function body with `// … 12 lines …`, which is a comment in Rust and a syntax error in Python, YAML or shell — so a skeleton could not be pasted back or read by a tool that parses it. It now uses `#`, `--`, `;` or `//` as the file requires.

- A test runner's status line keeps the name of the test. `--- PASS: web::tests::a11y_preserves_refs` had the test name replaced by a redaction marker, because a long path-shaped identifier after a `:` looks like an assigned credential. The one token saying WHICH test ran was the one removed. Measured in one agent's transcripts: 215 occurrences.

- On Windows, the savings ledger's cross-process lock is now actually taken. Two tokenade processes writing while a third rotates the ledger is the race that lock exists to close, and on Windows it was never closed: the lock was requested on a handle opened for appending, and Windows refuses to lock one of those, so the request failed and the result was discarded. The rotation then rewrote the file with nothing holding anybody off. Taking the lock for real needed a second change, because Windows locks are mandatory rather than advisory: a lock on the ledger locks tokenade out of reading its own file, so the lock now lives on a small companion file beside it and every writer, rotation and rollup agrees on that one. Unix and macOS were never affected.

- On Windows, tokenade's scratch cleanup now reclaims anything at all. The sweep keeps a directory whose owning process is still running and deletes the rest, and the liveness question had no Windows answer: it replied "still running" for every process id, including ones that had never existed, so nothing was ever collected on that platform while Linux and macOS reclaimed gigabytes. Asked with `OpenProcess` now, reading "no such process id" apart from "it exists and belongs to someone else" — the second is alive and is kept, which is the same rule the Unix side applies to its own errors.

- Tokenade's scratch cleanup reaches every directory it creates. The sweep knew one filename prefix and the temporary directories are written under two, so half of them were never collected: 6.0 GB on one machine, with `/tmp` at 96% full and builds failing for lack of space.

- Auditing a `CLAUDE.md` cascade from a relative path reads the same files as from an absolute one. It resolved the starting directory differently in the two cases, so the same audit run from `.` and from its full path disagreed about which instruction files apply.

## 1.1.8

- The savings tokenade claims for recovering a fold are bounded, and it stops claiming any when it recovered nothing. `tokenade expand-ref` credits the re-run it spared you, and it was crediting the whole stored blob on every branch — including the two that hand back no content at all. Asking for a blob too large to dump prints a pointer instead: on one machine that branch was the single largest saving in the ledger, 393,740 tokens for a sixty-token banner, and those tokens had already been counted once when the fold saved them. A `--grep` that matched nothing was the same. Neither credits anything now. The branches that do return content — a question answered, a fold served, matching lines — subtract what they put in your context window, because that round only happened because the first fold gave you less than you needed. And the figure is capped at one truncated re-run, with no extra credit for the grep-and-read dance a truncated tail normally costs, since this row *is* that dance. On the machine this was found on, the class fell 60%.

- Savings recorded by the hook itself are bounded like every other kind. Each event is discounted to what your agent's harness would really have put in front of the model, and the rule that picks that limit matched the wrapper spelling of the hook's name but not the plain one — so rows written by the Claude, Cursor and Antigravity pre-tool hooks fell through to "no limit known" and were credited in full. 33 rows and 30,712 tokens on the ledger this was measured on, all of them a shell command's output. Separately, the estimated ledger's exemption from that limit is now per kind rather than wholesale: per-turn accounting figures (context compounding, batching, tokenade's own overhead, brevity) legitimately exceed a per-call limit and keep their full figure, while anything that is one tool result stays capped — including any lever added later, which now inherits the bound instead of the exemption.

- The local LLM proxy now installs itself on **every** path that should install it — `tokenade install`, `tokenade upgrade`, and the once-a-day check — for the agents it adds a feature to, and for no others. Three faults stacked behind one another. The daily check spawned `tokenade llm-proxy auto-install`, a subcommand the parser did not recognise: it fell through to the serve fallback and came back as `unknown option`, exit 2 — spawned detached, exit code discarded, and its 24-hour marker stamped BEFORE the attempt, so the file said "checked today" while nothing had run. It had therefore never run once, on any machine. Behind that, the check treated a config record as proof the proxy was installed, so every machine set up before the supervisor existed (2026-08-31) was skipped forever with its agent pointing at a port nothing listens on. And behind that, such a machine could not be repaired even by hand: `install` rightly refuses to re-point an agent that already points at the proxy, and the automatic path swallowed the same refusal in silence — what was missing there was never the config, it was something serving it. Measured on a dogfood machine: record from 08-25, no service, no listener, eight days up. Now the three paths share one function, a config already pointing at us gets the supervisor alone (and is never rolled back, since this pass did not write it), and the service carries `Restart=always` so a crash comes back on its own.

- A launcher prefix no longer hides an interactive program from the hook. Tokenade refuses to wrap commands that need a terminal — editors, pagers, `top`, `ssh` — because wrapping them pipes their output and they never return. It recognised them by the first word, so `timeout 60 vim notes.txt`, `nohup less big.log`, `env EDITOR=x vim f`, `command less f`, `setsid top` and `nice -n 5 htop` all read as the launcher, missed the list, and were wrapped; `cd /tmp; vim f` was passed through while `cd /tmp; timeout 60 vim f` was not. Each of those hangs your agent's shell until its own timeout fires. The check now asks the same question of the peeled command as well as the typed one, through one shared gate — which matters because the gate existed four times over, once per agent envelope, so Cursor and Antigravity would otherwise have kept hanging on a spelling Claude Code had been taught to skip. The cost is that `timeout N ssh host 'cmd'` is no longer compacted, exactly as the bare `ssh host 'cmd'` has never been.

- Tokenade stops keeping folded log lines it will never serve you again. The fold store has a seven-day horizon, and the command that reads a fold has always enforced it against the fold's birth: past seven days it refuses the fold and deletes it. The daily cleanup measured the other clock — when the fold was last touched — and re-folding the same output touches it without changing its birth, so a fold could sit on your disk indefinitely while every read of it was guaranteed to refuse. Measured on a real install: one fold born on 2026-08-03, still there on 2026-09-01 at 66.7 MB and 1.76 million lines, walked past by twenty-three consecutive daily sweeps. The cleanup now draws the line in the same place the reader does; on that install it took `~/.tokenade/fold_store.db` from 66.7 MB to 20 KB.

- `tokenade scrub-secret` says what it did not scan. It walks tokenade's own stores — the debug log, the gain ledger, the dedup and search databases, the stash — and answered `no occurrences found`, which on a command whose whole subject is a leaked credential reads as "your machine is clean". The largest record of tool output on a machine is your agent's own transcript, which tokenade writes nothing to and therefore never scrubs. All three outcomes now bound themselves and name the verb that reaches the rest (`tokenade redact <file…> --in-place`) — including the successful one, where the reassuring reading is strongest: you have just learned the secret WAS in the logs, so it is probably in the transcript too.

- The checks tokenade runs over its own source read the whole file again. Several build-time guards lint the shipped half of a source file, skipping `#[cfg(test)]` blocks by counting braces — and a test fixture carrying a brace inside a string never closes, so the scan ran to end of file and everything below became invisible. Measured on this repository: one file was read to line 1,500 of 3,736, hiding 24 shipped items from every guard built on that sweep, with three more files partly hidden. Strings, raw strings, character literals and comments are now skipped, and the sweep is one shared piece of code instead of three copies — two of which had grown their own version of the same bug, one with a comment arguing the case for it. No user-visible behaviour changes; what changes is how much of tokenade its own guards can see.

- `tokenade health` watches two compaction levers it had never seen. The check that lists levers with no activity is kept honest by a sweep of the source, so the list cannot drift — but the sweep read only one of the ways the product books an op, and missed both dedup levers declared through a struct (`tokenade read`'s re-read dedup and `tokenade wrap`'s repeated-command dedup). The consequence was the reassuring kind: an unwatched lever can never be reported dead, and the row's own note explained the gap away by calling one of them an obsolete spelling — while it had fired eight times in the last thirty days on the machine where that note was written. The sweep now reads that shape too, and proves it still does by naming one op per shape rather than counting them.

- A shell keyword inside a string no longer stops tokenade from reading a command chain. `echo "=== rows iterated for the totals ==="; grep -rn x a.rs` was declared bash control flow because of the `for` inside the message, so the chain could not be split and was routed and labelled by its first segment — usually `cd`, a command that prints nothing. Measured over 108,974 real agent commands: 9.6% were called control flow on a quoted keyword alone, and 4,363 of those are chains whose head produces no output, 4,281 of them `cd`. That is where a `cd` row in `tokenade gain` came from, and the advice to "write a compactor for `cd`", which fired 92 times. Quotes are now read before keywords are looked for, and an unterminated quote is still refused rather than guessed at. Separately, `cd … ; tokenade wrap '<cmd>'` now resolves to the tokenade segment as its own routing note always claimed, instead of being compacted a second time under a `cd` label.

- `tokenade impact` attributes more of a file's callers, because a test declaration no longer decides who depends on it. A test helper named `out` or `scratch` put that name into what the file was taken to declare, so every file calling anything so named became a caller the report had to give up on; and a test declaration in another file gave a real name a second home, which abandons attribution for all of its callers at once. Measured here: `disclose.rs` went from 13 unattributed callers to 4, `redact.rs` from 6 to none, and `code_intel.rs` from one confirmed dependent to four. This is sound rather than convenient — a `#[cfg(test)]` item is only compiled for its own crate's test build, and each file under `tests/` is a separate crate nothing links back to. The same report also got faster: `impact` on a large file went from 0.91s to 0.43s.

- `tokenade map` and `tokenade impact` recognise a test file in any language, not only in Rust. The two signals they had — a test attribute and a `mod tests` block — see nothing in a Python, Go or TypeScript project: measured on an indexed Python repository, they found 0% of its symbols where the path rule finds 63%, so the map read a codebase that is two thirds test as if all of it were code. A file counts as a test by where it lives and what it is called (`tests/`, `__tests__/`, `spec/`, `test_x.py`, `x_test.go`, `x.test.ts`, `conftest.py`), never by a bare name — `test_connection.rs` is an API function's file, and `testing/` is left alone because libraries ship test helpers there. A test tree that the code ranking pushes off the map is now named in the truncation line instead of vanishing, and `impact` on a test file no longer says it contributed no symbols one line above counting them.

- `tokenade map` ranks directories and files by code, not by how many tests sit beside it. The map keeps the densest 80 directories of a repository, and 44% of this workspace's indexed symbols are test declarations — enough to decide what you see. Measured before the change: eight `*_dispatcher/` directories holding ONE function each were kept on the strength of eight to twelve tests, while directories with real code were dropped, and three of the ten "top files" owed their place to a test module. Tests are counted beside the code now (`2 files, 6 symbols (+9 test)`) rather than folded into one number, and the header still reports every symbol indexed — what changed is what ranks. Same rule as `impact`, so a half-test file does not read as twice its size in one command and not the other. Rust for now: a test attribute or a `mod tests` block; a Python `def test_x` or a `*.test.ts` is not recognised yet.

- `tokenade impact <file>` no longer counts a file's own tests in what it offers. The command answers "what depends on this file", and nothing outside a file can depend on its `#[cfg(test)]` declarations — but they were listed and counted with the rest, so `systemd.rs` reported `declares (27 symbols)` and `fn (20)` for seven real functions. It matters more than the count: each kind gets a twelve-name window, and five of the twelve shown there were test names. Measured on this workspace, 9,592 of 17,763 indexed functions are test functions. They are now counted apart — `fn (7)` plus a line saying how many test declarations exist — and they are still there to find: `tokenade query <name>` returns them, and `--json` gained `test_symbol_count` with the full list. Two signals identify them, because each misses what the other catches: a test attribute (`#[test]`, `#[tokio::test]`), and sitting inside a `mod tests` block.

- `tokenade gain` no longer prints two percentages side by side that count different things. A row read `auto-compact 38× −91%  89% on 08-31`, where `−91%` is a saving rate and `89%` is the share of that op's volume that fell on one day — same unit, nothing between them, and the second reads as "saved 89% that day". It now reads `(89% of it on 08-31)`. The note itself exists to stop a one-day figure being read as a trend, and it is still shown only when the day owns at least 70% of a well-dated window across five or more calls.

- `tokenade web` says why a target failed when you pass several, not only when you pass one. Fetching one URL has named its cause for a while — a closed port, an unknown host and a timeout are different problems with different fixes — but the batch form answered `fetch/read failed` for all of them, plus a typo in a path and a directory. That is the call shape tokenade's own guidance tells you to prefer, because several URLs in one call fetch concurrently. Both forms now print the same line: the transport's own verdict for a URL (with the `TOKENADE_DEBUG_LOG` pointer that shows every attempt), and the operating system's message for a local path. A batch stays partial rather than all-or-nothing — the readable targets are still served, the failing one is named, and the exit code still reports the failure. The reason itself is now in English, like the sentence it appears in.

- The stash banner for a command no longer sends you to a command tokenade refuses to run. When a fold stashes the output of a command rather than a file, the footer's advice for getting an exact value read `grep the original source (re-run via `tokenade raw <cmd>` if needed)`. But `tokenade raw` refuses the whole safe class — `grep`, `rg`, `find`, `ls`, `wc`, `head`, `tail`, `awk`, `sed`, `cat` — because re-running spends the original call's tokens a second time, and those are exactly the commands whose output gets stashed. Following the advice cost a turn to be told to come back to `expand-ref`, and the same output already carried a second banner offering the complete pre-fold bytes with no re-run. The footer now names the verb that answers without re-executing anything: `tokenade expand-ref <hash> --grep <pattern>`. That was deliberately absent before, because grepping a head+tail preview used to read as "never printed" when the line lived in the middle — a miss now says what it searched, so the trap is closed and the verb is safe to recommend. When the stash came from a FILE the footer still points at the original path, which is complete, verbatim and cheaper still.

- `tokenade expand-ref --grep` no longer answers a miss in words that mean "that line was never printed" when all it can mean is "not in what this hash holds". `expand-ref` is the way back after a fold already took the bytes away, so what it answers ends the search one way or the other — and a stash is not always the complete output: a fold-store hash is the source byte for byte, while the stash a deep fold leaves behind is often the folded summary. Measured on `grep -rn 'fn ' filter.rs` here: 280 lines printed, 207 kept under the hash, and a symbol living in the 73 the fold elided came back as `0 matching line(s) of 207 total` followed by `nothing matches …, ignoring case either` — two lines that both read as a statement about the command's output. The count now says what it counts (`of 207 held under this hash`) and the miss names its scope and why it can be smaller than the run. Which kind of hash it is is not guessed: naming the scope is true for both. The number itself is not repeated — it was already on screen, under a label that overclaimed.

- `tokenade health` no longer says a plugin bridge is compacting when it stopped months ago. Three lines claimed, in the present tense, that an agent bridge was firing — from evidence with no time bound: the ledger-backed bridges (opencode, pi, kilo-code, cline, openclaw) asked only whether a saving had **ever** been recorded for that agent, and the Hermes check asked whether a marker file **exists**, a file written once and never removed. A bridge that stopped loading six months ago still read `plugin active — tool-result compaction firing`. Both now use one rule with a thirty-day window — the same window the dead-lever row already uses — and a bridge that has gone quiet says when it last worked instead of claiming it is working. "Never seen" and "gone quiet" stay different answers: one tells you to start it once, the other that it stopped, and telling someone whose bridge just broke to start it once is advice they have already followed. One more line said the same kind of thing and changed with them: `PreToolUse hook covers Read (dedup + slice staging active)` reads your matcher, so it knows those levers *can* run and nothing about whether they have — it now says `can run`, and the lever row answers the other question.

- `tokenade health` also tells you when every hook agrees on a tokenade you never type. The split check added earlier names hooks divided across two installs; it answered "every hook runs the same tokenade binary" whenever there was only one — whatever that one was. But a machine where **all** the hooks point at a single stale install has no disagreement to report, so it got an OK: true, and silent in exactly the case the check exists for. It now asks the second half too — is the binary they agree on the one a bare `tokenade` runs? — and names both paths when it is not. A hook path that does not resolve at all counts as "not the one you type" rather than being assumed to match, which is the difference between reporting a dead install and blessing it. With no tokenade on PATH nothing is claimed, because there is nothing to compare against.

- `tokenade health` says how old its licence figures are. The plan and usage on that line come from a cached record — the check has always read them without a network call, deliberately, so that `health` works offline — but the line said `license active` flat, which is a claim about right now made from a record that may be days old. It now names the age past an hour (`last checked with tokenade.net 9d ago`) and stays silent below that, because a fresh cache is the normal case. A machine that has been offline, or whose usage reports are quietly failing against a corporate proxy, shows it here rather than at the moment tokenade pauses mid-session.

- `systemctl status` with no unit named is folded now — it was passing through whole. It is a different document from a unit's status: a unit reports `Loaded:` and `Active:`, and the manager reports `State:`, `Units:`, `Jobs:`, `Failed:` and then the cgroup tree of every process on the machine. The detector only knew the first shape, so the second came back untouched: 5,633 bytes in and out, of which seven header lines carried the whole answer and sixty-five were the tree. Every header key is kept verbatim — each one is a fact you asked for — and the tree is counted rather than shown, because someone asking whether the machine is healthy is not asking for Chrome's renderer PIDs. 5,633 → 536 bytes for `--user`; the system-wide form goes from 4,964 to 494. A unit's status is untouched, and a tree too short to be worth a banner is left alone.

- Commands with a compactor of their own now also reach their per-subcommand compactors. Tokenade keeps compactors named for a subcommand (`go test`, `systemctl list-unit-files`), and the lookup that finds them lived in the last branch of the dispatch — so every program important enough to have a branch of its own returned before reaching it, and its subcommand compactors were unreachable. That is the exact gap the lookup was added to close, one layer up. Measured here: `systemctl list-unit-files` folded nothing, 10,729 bytes in and out, with its compactor sitting in the table; it now folds to 5,156 (52%), and `systemctl show <unit>` from 6,238 to 2,305 (63%). 204 branches, 76 of them own subcommand compactors, and 24 fell back without asking — `gh` returned unconditionally with 58 `gh_*` compactors behind it. The lookup is now one shared piece of code the branches call. `systemctl status` with no unit is still not folded: its output is a cgroup tree that no compactor describes, and asking the question does not invent an answer. The other branches were checked rather than assumed: after these two, no remaining branch owns compactors for actual subcommands — the rest are sibling programs (`ssh-add`), flag variants (`cat -n`, `tail -f`) or DNS record types, all already handled by their parent, and a check now fails the build if a new branch appears that needs the lookup and does not use it.

- `tokenade health` watches every compaction lever, not a quarter of them. The "N lever(s) with zero fires in 30 days — possible dead routing" row read from a hand-kept list of 8 op names, while the ledger writers book **26**; the read hook alone books fourteen, of which four were watched. So `health` could report "content dedup: never fired" on a machine whose read dedup works perfectly — the one that fires there books a name nothing was looking for — and, worse, a lever that really was dead among the unwatched ones was never reported at all. The table now covers every op the product books, and a check enforces that: adding a lever without listing it fails the build. And when most of the table is silent, that is said **once** — most levers at zero on a ledger that has rows points upstream of any single lever, so the row now names a few, counts the rest, and points at the hook-binary checks that name the usual cause, instead of printing twenty-two lines you scroll past.

- Upgrading a wrapped MCP server no longer gets undone by `mcp-wrap uninstall`. Wrapping rewrites a server's launch command to `tokenade mcp-proxy -- <your command>` and keeps a copy of the original; unwrapping restored that copy. But you upgrade an MCP server by editing its version in the config, and while it is wrapped that edit lands in the wrapped command — so unwrapping put back the command from the day you wrapped it, months earlier, with nothing saying an edit had just been discarded. Measured on a real `~/.claude.json`: after bumping a server to `@2.0.0` and adding `--read-only`, `env` and `timeout` came back intact (those are yours, tokenade never rewrites them) and the version bump did not. Unwrapping now reads what the entry launches **today** — the part after `--` — and falls back to the stored copy only when there is no readable command there. A `--` inside your own arguments is untouched; only the first one is tokenade's. Same rule for all three config shapes: Claude Code's JSON, Codex's TOML and Reasonix's plugin array.

- `git status` is folded on a clean tree in every language, not only in English. git translates its human-readable output, so the reader that looks for `nothing to commit` never matched off English and the whole thing went through untouched: measured on one repository in the same second, `158 → 19` bytes under `LC_ALL=C` against `188 → 188` under `fr_FR.UTF-8` — 89% against nothing, on the command an agent runs more than any other. The structural fact needs no language: staged, unstaged, untracked and conflicted files are all TAB-indented and git never prints an empty section, so zero indented entries means nothing to commit. The branch line and its ahead/behind count are kept and the translated closing sentence is replaced by the same `clean working tree` the English path emits, which keeps **more** than the English fold does — that one drops the branch. 188 → 102 bytes here. A status whose branch name is shorter than the replacement phrase comes back untouched rather than longer. A tree with changes was already folded off English and is unchanged by this.

- Coloured command output is no longer withheld as binary. `grep -rn --color=always 'fn ' <file>` — 558 bytes of ordinary readable text — came back as `(Binary content — not shown as text. Inspect with: file <path>, xxd <path> …)` with the bytes moved to the stash, and the only way out was to run the command again without colour: the exact round trip tokenade exists to save. The cause is that `ESC` is a control byte and the binary heuristic calls anything with 5% control bytes binary, while coloured output is nothing but `ESC`. Measured here: `grep --color=always` is **11.9%** escape bytes, `cargo test --color=always` 4.1%, `git -c color.ui=always log --graph` 2.9%. The file case is worse than the command case — a CI log captured from a terminal carries its escape sequences, so `tokenade read build.log` answered "binary" about the log you asked it to summarise. Escape sequences are now set aside before the question is asked, on both sides of the ratio, so a buffer that is 90% colour and 10% NUL bytes is still binary and an `ESC` that opens no valid sequence still counts as a control byte.


- `tokenade health` tells you when your hooks are split across two different tokenade installs. A machine can easily end up with two: a `cargo install` from months ago and a current one, or a distro package beside a user install. Both exist, both are spelled correctly in your agent's config, and nothing fails — the hooks pointed at the old binary simply compact less, quietly, forever. Measured on the machine tokenade is developed on: `~/.claude/settings.json` and `~/.gemini/settings.json` each had hooks on a **June build of 0.5.1** alongside hooks on the current one, while `health` printed `OK all agent-config hook paths resolve` and `OK installed hook commands match the expected tokenade shape` — both true, and both answering a neighbouring question. The report now names each binary and the config files that point at it, and `tokenade install` puts them all back on one. A binary reached twice through a symlink is still one install and is not reported.

- The same report says which `tokenade` your shell actually runs. It used to print the running process's own path, which can only ever describe the copy that already won. If a second copy is on your PATH it is now named, in PATH order, along with the fact that PATH order alone decides between them — a shell rc, an editor's integrated terminal, a systemd unit or a Makefile can each change the answer without telling anybody. When no `tokenade` is on PATH at all, that is said plainly: agents that call the command by name will not find it.

Since `query` started showing `called by:`, it was visible: the list named callers in files that no longer exist. A modified file was already handled correctly.

The command's help announces "where is this defined, and who calls it"; the second half was returned nowhere, neither as text nor in `--json`, even though the call graph was being built and stored. These commands change nothing, yet each re-serialised the whole index and wrote it back to disk before answering, even when not one file in the project had moved. On a 3,980-file project that meant 51 MB written per query, and 74 ms of the 243 ms spent preparing the index. The index is now rewritten only when a file has actually changed: the query goes from 319 to 244 ms and writes nothing. A file added, modified or deleted is still picked up immediately.

As a result none of their fields was indexed — measured on a real Python repository, 653 distinct attribute names across 176 files, all unfindable. Across the 60 most-used attributes of that repository, `query` answered with the field 0 times (and 30 times with a function whose name merely contained the string, which is worse than no answer); it now answers 60 times out of 60, each line carrying its class: `field AuthenticationError.num_retries — exceptions.py:146`. Measured here: a third of one cache was dead space containing source code deleted weeks earlier. All five are compacted now.

Redaction now happens on the way in, and the other words of the comment stay searchable. `tokenade scrub-cache` also covers that index for caches written before this fix.

The binary was giving two answers to one question.

Each interface block was cut to its first three lines plus a packets/bytes summary, which made the MAC address and the `RX/TX errors … dropped …` lines disappear with neither count nor marker — that is, precisely what you run `ifconfig` to see when a link is misbehaving. On a real machine, `RX dropped 90792` on the Wi-Fi appeared nowhere. A faultless interface now says so explicitly (`errors/dropped: none`) rather than staying silent, and the remaining lines are counted.
- A folded list of records names the ones it did not show. `pacman -Qi`, `apt show`, `systemctl show` and any stream of `Key: value` blocks kept the first records and then ended on a `... (+86 more)`. Each record names itself in its first field, and eighty-six package names is not the same information as the number eighty-six: the elision now lists them, and counts those that do not fit on the line. A stream whose records do not name themselves (a timestamped log, a numbered list) keeps exactly its previous behaviour.
- `ip -d` finally returns the detail you asked it for, and `ip -s` becomes readable. The `ip` compactor read only two tokens of the `link/…` line, so the block `-d` exists to produce (`promiscuity`, `minmtu`, the `gso_*`/`tso_*` sizes, `parentdev`) was exactly what it threw away: `ip addr` and `ip -d addr` returned the same text. And the counters from `ip -s link`, printed on two lines by the tool, arrived separated from their column names, so you had to count columns to read `91637 dropped`. They are now joined (`RX 49685952 bytes, 323833 packets, 0 errors, 91637 dropped`), uninteresting zero columns are dropped, and the error columns are shown even at zero so that an absence cannot be mistaken for a removal.
- `systemctl list-units` finally folds the healthy part of the list. The fold recognised as healthy only units in `running` or `exited`, two values of the SUB column among many: a device is `plugged`, a mount point `mounted`, a target or a timer `active`, a socket `listening`. On a real machine with 623 units, exactly one line was folded. The rule now rests on `loaded` + `active`, which is what the message already displayed: 121,748 bytes returned as 36,677 instead of 111,718, without a single abnormal unit disappearing. An isolated healthy unit is still written out rather than replaced by a line announcing there was one.
- `tokenade query` finally finds constants declared inside a function body (Rust). The index set aside everything declared inside a function so as not to fill up with local variables, but it already let nested functions through, so a Rust `const` or `static` — a compile-time binding, not a runtime local — stayed unfindable. On this repository: 379 declarations concerned, 294 distinct names, and the index goes from 23,186 to 23,613 symbols. Local variables stay excluded, and the other languages do not change.
- `tokenade query` finds Rust macros and TypeScript abstract classes. A `macro_rules!` definition did not exist for the index at all — neither function, nor type, nor member — although its declaration is the only place to read what a macro generates: across a corpus of real Rust projects, 105 definitions and 90 distinct names were unfindable. They now appear under their own `macro` label. On the TypeScript side, `abstract class Foo` is a different node from `class Foo` in the grammar, so an abstract class — the one carrying the contract, and therefore the one you are looking for — was the only one you could not find.
- `tokenade query` finally finds C and C++ `#define`s. A `#define MAX_PATH 4096` is what a C constant is, the language having no other way to write one at file scope, and the index reached none of them. On a real 1,667-file C project, reachable symbols go from 62,315 to 76,696 (+23%) for 3.3% more storage. The callable form (`#define SQUARE(x) …`) is indexed as such, and both appear under the `macro` label. Along the way, `using Alias = T;` and `concept Foo = …;` — the two ways modern C++ names a type — are now types as well.
- `tokenade query` finds signatures declared without a body. `declare function foo(): void` and an `abstract` member of a TypeScript class are, in the grammar, different nodes from an ordinary function or method, so they were unfindable, although that is precisely the half of a contract an implementer goes looking for. The same for `type X = Y` in Go and for a Rust trait's `type Item;`. A generic constraint (`Iterator<Item = u8>`) stays excluded: it is not a declaration, and indexing it would answer "where is Item declared" with every place that mentions it.
- `tokenade skeleton` finally shows file-level constants. A Rust `const NAME: T = v;` or a C `#define` declares a name and has no body to fold — it is a signature, exactly what a skeleton exists to show — and yet the line vanished into a `// … N lines …` while `tokenade query` found it. On real sources, a C file lost 21 of its 22 `#define`s and a Rust file its 13 constants. Constants declared inside a function are still folded with the body containing them, and the skeleton stays at about 9% of the file's size.
- `tokenade impact` no longer wastes its slots on a repeated name. The list of symbols a file declares shows only twelve per category; when a file declares the same constant in several functions, the name took up as many slots as there are declarations. `const (5): MAX_RESCUED, MAX_RESCUED, MAX_NAMES, MAX_CHARS, MAX_RESCUED` becomes `const (5): MAX_RESCUED ×3, MAX_NAMES, MAX_CHARS`. The count in parentheses is still the real number of declarations, and two more names fit on the line.
- The contents of an archive finally say what is inside. A `tar`, `zip` or `.crate` listing is grouped by directory beyond 200 entries, but the grouping started from the first path segment, and a release archive puts everything under a single directory. The result was one line repeating the total: 1,480 entries of a `.crate` returned `llama-cpp-sys-4-0.3.2/ (1480 entries)` and nothing else. Grouping now happens under the common root, which is named, and the real directories appear. An archive with several roots is unchanged.
- `git status` (the default form, translated by your locale) now factors out the repeated directory as `--porcelain` already did: on a tree with 213 modified files, the output goes from 13,717 to 5,338 bytes (62% saved instead of 11%). A directory holding a single file keeps its whole path, and every file stays under its own heading.
- A custom compactor (`.tokenade/filters/*.toml`) whose file does not parse — an invalid regular expression, a truncated TOML — was ignored in silence: it never fired and nothing said why. `tokenade healthcheck` now reports it as failed, names the file and gives the exact reason, and `tokenade trust-filters` no longer offers to approve an unreadable file (approving it did not make it work, but announced the opposite).
- `tokenade ask "question 1" "question 2"` now answers both separately. Quoted questions were joined into a single query, the rankings merged, and the question that scored best pushed the other off the list without saying so. The unquoted form (`tokenade ask where is auth wired up`) is still one question. The index and the models load only once for the whole set.
- `tokenade web --help` and `tokenade search --help` finally announce the batched form: both commands already accepted several targets in parallel, but their usage line showed only one, which led to making N calls where one is enough.
- `.html`, `.htm`, `.vue`, `.svelte` and `.astro` files are indexed at last: their declarations live inside a `<script>` block, which nothing descended into, so `tokenade query`, `skeleton` and `semantic` found nothing at all in a Vue, Svelte or Astro project, and nothing from the scripts of an HTML page. The tag is recognised whatever its case, and every symbol carries its real line in the file. What does not enter the index: data blocks (`application/json`, `text/template`, and the like), minified third-party libraries inlined into a page, and the single-character names they leave behind — on one library whose test suite contains 737 saved web pages, that avoids 11,000 symbols such as `r` or `i` which would have ranked the real API behind them.
- The debug log (`TOKENADE_DEBUG_LOG`) finally records every case where the 50,000-token output ceiling fires. The event existed but only one of the four paths emitted it: a ceiling applied to a web page or to a file read left no trace at all, which made a "truncated output" diagnosis impossible to confirm.
- A command preceded by a label (`echo "=== step 2 ==="; make build`) is compacted again by the real command's compactor. It was routed as an `echo`, which cost about 15% of the fold and lost the grouped summary of repeated lines. A leading `cd` was already handled; `echo`, `printf`, `sleep`, `true` and `:` are handled now too, and a chain containing only those is still routed as itself.
- Output more than half of which has been folded now carries its `tokenade expand-ref` pointer, even when it is short. The threshold looked only at the absolute number of tokens removed, on the assumption that "you can simply run the command again" — which is untrue for a snapshot of machine state: `systemctl list-units` lost 90% of its output, `df -h` 60%, `lsblk` 57%, with no way back to the original bytes, and running them again gives different bytes. Tiny outputs still write nothing to disk.
- `tokenade ask --budget N` shortens results before dropping them. When the ceiling was reached, the following results disappeared entirely while room remained: on a real search at `--budget 60`, two files were named and eight set aside, leaving sixteen tokens of the ceiling unused. A result that no longer fits whole now keeps its score and its path, and loses only the list of matching terms.
- When `tokenade exec` kills a script at the deadline, the message now says how to lift the limit: `--timeout <secs>` (default 30, maximum 600), and it makes clear that the output already shown is what the script had produced before it was stopped. The flag existed but was named only in `--help`, which made the timeout the leading cause of `exec` failures.
- An oversized custom compactor file (`.tokenade/filters/*.toml`) is refused on its size, before being read. That directory arrives with a cloned repository and is re-read on every command, so a 40 MB file — or a 2 GB one — charged its reading to every command you ran in that repository. The ceiling is 256 KiB, twenty times the largest compactor definition ever measured, and the refusal appears in `tokenade healthcheck` with its reason.
- A build or test whose failure the exit code swallowed is now named. A pipeline reports only its last stage's status, so `cargo test 2>&1 | tail -40` exits 0 however the tests went — and `| tail`, `| head`, `| grep` are exactly the operations reached for to keep output small, so the error always falls on the side of looking green. Measured across 89,151 recorded commands: 5,781 pipe a build or test runner into such a sink, and 830 of those handed back unambiguous failure evidence under a success status, against 13 reported as errors. Both `tokenade wrap` and `tokenade exec` now say so in one line when the status claims success and the output reports a failure, reading the raw output so a marker the fold removed is still caught. The exit code itself is untouched: turning `cmd | head` into a failure, where the producer dies on a closed pipe every time, would be worse than the silence. A command already reporting its own failure stays silent, and so does one that merely searches for the marker.
- `tokenade read` with nothing to read no longer hands back a pointer to nothing. With no file named and an empty stdin it answered with a recovery reference for the empty string — `~0 tokens / 0 bytes, identical to a prior call` — and invited you to ask it questions, while reporting success. It now tells the two cases apart: a bare `tokenade read` is a forgotten path and says so with a usage line and a failing exit code, the same as the other commands; an explicit `tokenade read -` whose producer legitimately emitted nothing (a `grep` that matched nothing, say) is a result and not a mistake, so it stays silent and succeeds. Reading a real file or a real pipe is unchanged.
- A mistyped flag is no longer accepted in silence. On `tokenade web` anything unrecognised fell through to the list of pages to fetch, so `tokenade web --json page.html` tried to download `--json`, printed `--json: fetch/read failed`, served the real page anyway and still reported success; a dropped letter in `--max-tokens` silently abandoned the budget and turned one page into a three-target batch. On `tokenade map` an unrecognised flag was ignored outright, so `--jsn` — one letter short of `--json` — printed the human map and reported success, handing prose to a caller that had asked for JSON. Both now name the flag and fail, as `search` and `exec` already did. In the same pass, `tokenade web` with no page at all used to print nothing and report success, so a typo read as a job done — it now shows its usage and fails, like every other command.
- The outline of a long page now describes its sections instead of its pictures. Each section is previewed by its first line, and on a page whose sections open with a figure that line is the caption: one encyclopaedia article came back with all three of its sections summarised as `"[1 of 2](/media/1/342664/159005)"` and `"[lions chasing a warthog](/media/1/342664/159006)(more)"`. The outline is what you read to decide which section to open, so a caption there costs tokens and tells you nothing. A caption now yields to the prose beneath it. It is a preference and never a rejection: a section that has nothing but a figure keeps it, rather than losing its preview altogether. A sentence that merely links to an image partway through is prose and is unaffected.
- `web`: section previews no longer describe a picture. A page whose sections open with a figure was previewed by that figure's caption instead of its prose — on a Wikipedia biography, three of four sections read as image captions.
- `wrap` and `exec`: the notice that a command exited 0 while its output reports a failure now recognises a Rust panic, a compile error carrying no diagnostic code, and an uncaught Python traceback. It is also no longer disarmed by a wrapper such as `timeout 60 cargo test`, which used to read as a run of `timeout` rather than of `cargo`.
- The 24h bypass reminder now reports the number of bypasses that actually happened. A `TOKENADE_HOOK_DISABLED=1` prefix written after a `cd` line — the common shape — was honoured but counted as none, while one written at the start of the command was counted twice, and `TOKENADE_HOOK_DISABLED=1 tokenade …` counted as a bypass although it bypasses nothing.
- `pack`: the bundle header now accounts for every file in scope. Files skipped for being binary or over the per-file cap appeared in neither the included nor the omitted list and were named nowhere, so the two counts did not add up to the scope; and the header called that scope "all git-tracked files" although the bundle also carries untracked files git does not ignore.
- `web`: when a page is behind a bot wall, the notice now tells you what you can actually do — an immediate retry returns the same page, and the way through without a browser is to save the page from one you are signed in to and hand tokenade the file. It previously listed the libraries a stealth fetcher is built from, which is of no use to the caller holding the challenge page.
- `exec`: when stdout hits the cap, the notice now names `--cap`, the flag that actually raises it. It named `--stdout-cap`, which the same binary rejects with `unknown flag` — so following the advice cost you the turn and the output. `--script-file` is also documented in `exec --help` now; it worked but appeared nowhere.
- A `find` / `ls -laR` rollup now says outright that no individual path is listed in it, and how to narrow the command to see them. It summarises by directory and extension, and depending on how the output reached you there was not always a way back to the paths.
- `evict-stale --help` now documents `--models`, the flag that deletes the local model weights. Those sit on no expiry and are by far the largest thing tokenade keeps, and the help said "No flags" — so the only way to reclaim that space was not discoverable from the command itself.
- `exec --help` now lists `--sandbox`, `--sandbox-net` and `--json`. All three worked and none was mentioned, while the same help spent a paragraph explaining what the sandbox does and does not cover.
- `exec` now offers `tokenade expand-ref <hash>` when a fold drops content, as `wrap` already did. The check it used looked at how large the remaining text was, so the more effectively something folded the less likely you could get the original back — a 400-file `ls -laR` collapsed to a two-line summary with every path gone and nothing to recover them by.
- Aligned command tables are compacted even when the handler for that specific tool declines to fold them. tokenade tries the tool-specific handler first because it knows what the columns mean, but if that hands the table straight back the generic column fold is now used instead of serving the table unchanged — on `lsof`-shaped output that is 9,427 bytes down to 3,973 rather than 9,426.
- `read --prompt`: when nothing in the document answers your question, the reply says so even when what comes back is an outline. It already said so for documents handed over whole, but the outline is rebuilt after that notice is added and dropped it — and a list of section headings reads even more like a chosen answer than the document does.
- `web --prompt` now answers the question on a web page. The flag was accepted and listed in the usage line, but only the PDF/Office route ever used it — an HTML page came back byte-for-byte identical whether or not you asked something. You now get a scoped extract when the page answers, and the page plus a note saying it does not when it doesn't.
- `web --max-tokens` now says what it bounds. It caps the input that gets parsed, not the reply — the page is still converted whole so its tail is not lost — so the answer came back the same size with the flag as without, with nothing said about it. The usage line explains this, and a note tells you when the cap actually engaged.
- `skeleton --budget` now tells you when it cannot apply. Across several files the ceiling works and the footer reports what it withheld, but the first file is always shown in full — so on a single file the flag could never do anything, and did nothing without saying so.

## 1.1.6

- A command that produces several megabytes of output now comes back in about a second and a half. The largest outputs used to take minutes, and the more there is to hand back, the wider the difference.
- A search whose matches span a large part of a repository is about fifteen times quicker once tens of thousands of files are involved, and stays quick as that number climbs.
- Reading a PDF is up to four times faster, and the bigger the document the bigger the difference.
- Reading an oversized image is about three times faster.
- `skeleton`, `map` and `query` are close to twice as fast on large source files.
- Every command tokenade wraps carries about a tenth less overhead than it did, on top of the reductions above.
- The download is smaller than the last release, so a first install and every update since take less.
- tokenade's own record of what it masked before sending now says WHICH rule masked it, not only how many values. A rule that starts catching something it shouldn't used to look exactly like a busy week.
- `gain` no longer reports two different kinds of estimate as one number. Most of what it credits to code-intelligence commands comes from a file it actually read and counted; the rest rests on a published figure that is not ours. Each is named and totalled separately now, and both stay out of the measured headline.
- `gain` now says when a single day's traffic accounts for most of what an operation's percentage is built from. A seven-day figure assembled almost entirely from one busy day read as a trend; the day and its share are named beside it now.
- Fixed: a failing test could come back with its own name replaced by `<redacted>` — the single line you run a test suite to get. Test names survive now, and nothing that was masked before stops being masked.
- `uninstall` now says how much disk each thing it removes will give back, in the dry-run as well as for real. On an install that has downloaded local-agent models that is tens of gigabytes, and the line used to name only the path.
- tokenade now gives back the disk its own databases had stopped using. Four of the five kept every page they had ever freed and never returned it: on a well-used install that was a third of the largest one. They are compacted once a day, and only when there is enough dead space to be worth it.
- Fixed: when tokenade answered a re-read of part of a file by pointing at lines it had already delivered, the recovery command it printed alongside could name a copy that had since aged out of the cache — leaving no way back to those lines. It now only makes that claim while the copy is still there, and pointers to dropped copies are cleaned up instead of accumulating.
- Fixed: with several tool calls running at once, records written to tokenade's own counters could be cut into each other, so the dashboard under-reported how many secrets it had caught, and two internal counters could read back a number that was neither of the two written. Measured on a real install: 17 damaged rows in a thousand.
- Fixed: `tokenade raw 'some command'` — the quoted form every other tokenade command takes — always failed, reporting the whole command line as a file that does not exist. Both the quoted and the plain form work now.
- Reading a file through tokenade is about twice as fast, and the bigger the file the larger the gap: a 200 KB read that cost roughly four tenths of a second is now under a seventh of one.
- Wrapping a command costs about three times less than it did. On a command that finishes instantly the overhead is now around a hundredth of a second; on anything slower than that, close to nothing.
- `gain --recent` reports the last seven days instead of everything since the ledger began. A compactor rebuilt last week no longer shows the number it scored before the rebuild.
- Every wrapped command used to pay a startup cost that grew the longer you had been using tokenade — on a well-used install, around a fiftieth of a second on each of the two checks a tool call makes. That cost is now flat, and does not grow.
- Fixed, on Windows: text lifted from a page whose headings are set letter by letter came back with the last letter of each word split off, so `Hello` read as `Hell o`. Every line, and only on Windows. Those words are rejoined whole now.
- Fixed: when tokenade answered a repeated read by pointing at the copy already in your context, and that answer did not land, the fallback that serves the file in full could fail to fire while several reads were in flight — leaving the read to repeat. It fires reliably now.
- Fixed: when the recovery copy could not be written — a full disk, a read-only cache — the folded output still told you to run a command with a reference nobody had produced. It now names only the way back that still works.
- Fixed: with several tool calls running at once, the counter that tracks how much output a session has been handed lost some of them, so a context-heavy session could look light and never get the tighter handling it was due.
- `evict-stale` now reports the local-agent model weights it holds — the largest thing tokenade stores and the one nothing ever swept — and `--models` removes them.
- `healthcheck` now says how much disk tokenade is holding and what the biggest part of it is. Past a few gigabytes it also says how to get it back.
- tokenade now keeps its own disk use inside the limits it always documented. Two of those limits were only ever applied by a command you had to run yourself, and the rest had none at all, so what tokenade held on your disk only ever grew. Once a day it now trims: recovery copies past the documented ceiling, the short-lived bookkeeping it leaves between tool calls, and its own backups once they are a month old. A report bundle you generated yourself is never touched, at any age. The one thing this can cost you is `expand-ref` on the very oldest folds — the ones already past the ceiling.
- A plan that will destroy something now says WHAT it destroys, and a provisioning run that fails says which task failed. Both survived only as a count before — "1 to destroy", "failed=1" — with the line naming them folded away.
- `top` and `npm ls` now surface what you opened them for: a zombie or a hung process alongside the busy ones, an unmet or invalid dependency ahead of the two hundred healthy ones.
- `ps` now surfaces a zombie or a hung process alongside the busy ones. Ranking by CPU meant the two states you actually run `ps` to find — which cost nothing by definition — sorted last and were cut.
- When a large JSON array is folded to its shape, the items that do NOT share that shape are now shown rather than counted. The one record that differs from the other seven hundred is usually the reason the output was being read at all.
- Fixed: when a long log was folded, an error sitting in the middle of it could be dropped from what the agent was shown — a failed build read as a clean one. Failure lines are kept out of the fold.
- `skeleton` now shows a type's fields and an enum's variants. It used to report that a type existed and nothing about its shape, which sent the reader to open the whole file — the more expensive answer.
- Code samples from documentation pages arrive labelled with their language again, instead of an unlabelled block preceded by a bare word.
- Fixed: a markdown document handed back to tokenade — a page saved from `tokenade web`, a README printed by a command — could be read as some other format entirely and come back without its headings. A document that is plainly markdown is now read as markdown before anything weaker can claim it.
- Fixed: in an accessibility snapshot, a name containing a quotation mark — a heading that quotes an error message, an issue title — came back cut at the quote and glued to the element type. Those names are reported whole.
- Fixed: output produced before tokenade was watching — a conversation it was installed into part-way, or one resumed after a long pause — was counted as if tokenade had made it leaner, in a single lump. Only what happens under tokenade is credited now.
- An accessibility snapshot of a page now comes back about two fifths smaller instead of one eighth. A link that carried nothing but its own address is one line rather than two, and a list item holding a single thing is the thing itself.
- Fixed: in an accessibility snapshot, a list item holding several things could come back with its first child swallowing the rest, so two entries read as one nested inside the other. Items are reported the way the page has them.
- Fixed: a line of ordinary numbers — a timestamp followed by two counts — could be masked as if it were a payment card. Numbers in normal output come back as numbers.
- `ip addr` now answers in one line per interface instead of six. It used to cost what it costs to say four facts across six lines and four levels of indentation; the reformulation keeps every address of both families, every hardware address, every real lease attached to the address that holds it, the state, the size limit and any field we do not recognise — and takes about half the tokens, on a laptop as on a server with sixty interfaces.
- A page fetched twice in one session is delivered once, whether it was asked for through the tool or the command line. The second fetch still happens and is still compared in full: only a page that has not changed by a single byte is replaced by a line saying so, with the full text one command away. A page that moved is delivered whole, as before.
- A credential in an MCP tool result is masked wherever the server put it. Only one of the five places a server returns text was being checked, so a secret came back in clear through an embedded resource, through structured output, through a failed tool call and through a resource read. MCP is wired once and then wraps every tool result you receive, so this applied to every server configured. Image and audio payloads are still passed through untouched.
- A credential named by its field is masked even when its value looks like nothing in particular. An access key is forty characters of noise; what makes it a secret is the field it sits in, and in structured output that field is next to the value rather than in the same line of text.
- A session running a large-context model gets a cost column again. A 1M-context session names its model with a suffix no price list carries, so nothing matched and every dollar figure for that session read as zero — which looks like "this cost nothing" rather than "we could not tell". Bedrock and gateway model names are also reduced to something a price list knows, so a model that has no row of its own under those names still gets one.
- A Terraform value containing `/*` is no longer eaten. The block-comment stripper for HCL had no idea what a string was, so a bucket path or a regex holding those two characters swallowed everything up to the next `*/` — or to the end of the file when there was none. Real comments are still removed.
- A private key inside a JSON value, a config blob or a long log no longer reaches you in clear. The masking rule needed the key's closing marker to be present, and long values are shortened before masking runs — so the marker was often gone, the header was replaced, and the key material itself was served. Output that carried `<redacted-private-key>` could still contain the key. Every delivery command is now checked end to end against four credential shapes in seven document shapes.
- Reading a file can no longer cost you more tokens than not reading it through tokenade. When a file's extension already said what it was — which is nearly every file you open — the check that refuses a compaction bigger than its input was skipped. A tokenizer vocabulary came back a quarter larger than the original, an OpenAPI document five percent larger. Files that genuinely compact are unaffected.
- A page snapshot no longer carries a handle for every paragraph, table cell and image on the page. Those handles exist so an agent can click something; on things nothing can click they were pure weight, and they were a sixth of what a snapshot cost after everything else had been squeezed. Every handle an agent can actually act on is still there, including on the elements the page marks as clickable without saying so in their role.
- A file that is not written in English now comes back as its text. Source in any language, SQL, Terraform, protobuf, markdown and web pages all had the same fault: one string literal, one comment marker or one inline tag on a line was enough to replace every non-Latin character on it with garbage — Korean, Japanese, Greek, Cyrillic, accented French, emoji. Nothing said the text had been damaged, so it read as the file. English files were never affected.
- A document that is not written in English is now compacted at all. A single non-Latin character in the wrong place stopped the whole compaction for that file, and a paragraph of real prose that happened to sit next to one badge was thrown away as decoration.
- A blocked page served in a non-Latin language is now recognised as blocked. The check that separates a real page from a "checking your browser" wall measured length in a way that made any Japanese, Chinese, Korean or Russian page read two to three times longer than it is, so those walls were handed back as though they were the site.
- The savings figure tokenade reports is now the savings you actually got. On some shapes the count could not tell whitespace-padded output from a dense blob, so a figure could overstate a reduction by half again, or understate it by as much. Checked against the real token count over every capture we hold — browser snapshots, build logs, command output, source, web pages, compacted output — the reported figure now tracks it to within a couple of points, and the worst single case went from three times off to under a third. Some numbers get smaller as a result. What you saved did not change; what we told you did.
- A page snapshot taken from a browser now costs about 40 % less, measured on real sites rather than a sample we wrote ourselves. It was the single most expensive thing an agent driving a browser sent us, and the least reduced.
- A page snapshot now describes the page's real shape. Elements could come back attached to the wrong parent, so an agent was told a button sat inside a panel it was not in — and acted on that. Every element an agent can click keeps its handle, and every heading on the page survives.
- A link leaving the site is recognisable as leaving the site again. External destinations were rewritten to look like internal paths, so an agent reading a page could not tell where a link actually went.
- Build output from `npm`, `pnpm`, `yarn` and `bun` now compacts by about a third instead of not at all. These logs repeat one sentence per route, per file, per module — never the same line twice, which is all the old fold could see. Every warning, every path and every pairing is still in what you receive; the sentence is simply said once.
